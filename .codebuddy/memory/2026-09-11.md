### 结论（根因）

1. 柱状图（-28 / -149）：
   - `bar_chart` 形状只由**柱子矩形**组成（`ShapeRecognizer.detectBarGroups`），
     截图 bbox = 柱子并集 + `SCREENSHOT_HORIZONTAL_MARGIN=5` / `SCREENSHOT_VERTICAL_TOLERANCE=1`
     （`BarChartProcessor`），增长循环只吸收与当前框在 `COLLECTION_MARGIN=1pt` 内相交的元素。
   - 纵轴刻度数字距柱体左边界 13.7pt（-28）/ 40pt+（-149）、横轴类别文字距柱底 6.1pt、
     图例距柱底 27pt、单位说明在图表上方 → 全部 > 1pt，永远不会被吸收 → 截图里没有。
   - 连**纵轴那条线本身**都没进图：`ShapeRecognizer.groupShapes` 的 `overlapsWithYTolerance`
     要求两框 **x 方向相交**，纵轴在柱体左侧 8.5~13pt（无 x 相交）→ 单独成组，不被并入。
   - 实测 -28 两张图的 bbox 与"柱子并集 ±(5,1)"**完全相等**，证明增长循环一次都没吸收到东西。
2. 饼图（-18）：
   - 饼图（扇形贝塞尔填充路径）**没有任何 shape 类型**：`ShapeRecognizer` 未识别曲线填充图形；
     页面只识别出 11 个图例色块(rectangle) + 4 条引导线(polyline)。
   - 该截图实际由 **FlowchartProcessor** 产生（日志：`Page N: detected flowchart cluster with
     screenshot bbox [314.12, 596.336, 443.56, 637.937]`），命中条件是 `labelsWithConnectors`
     （≥3 文本 + ≥2 连接线），取的是"引导线组 + 1~2pt 内相邻文本"的并集 → 只截到饼图右上角 + 前 2 条图例。
   - 极端脆弱：`MIN_HEIGHT=40`，而该框去掉 ±1pt 后仅 39.60pt，只差 0.4pt 才通过。

## 柱状图截图区域修复（已实施，用户 5 条口径确认后）

用户口径：① 只到 plot+坐标轴+刻度/类别标签+图例；② 被图片覆盖的文字从文本流移除；
③ 本次只修柱状图（饼图不动）；④ 接受"只吸收短数字标签+细线"的保守策略；⑤ 允许改常量与分组规则。

改动 1：`processors/BarChartProcessor.java`
- 新增 `expandToChartRegion()`，在原有 1pt 增长循环之后：
  1. `isVerticalAxis` / `isHorizontalAxis` 吸附坐标轴：细长(`AXIS_MAX_THICKNESS=6pt`、`AXIS_MIN_LENGTH=20pt`)、
     距 plot 边 ≤ `AXIS_ATTACH_GAP=20pt`、与 plot 重叠率 ≥0.5；
     ⚠ 阈值必须 >3.2pt：-28 下方图表纵轴线宽 3.18pt，3.0pt 时会被漏掉。
  2. `expandToLegend`：`MIN_LEGEND_SWATCHES=2` 个边长 ≤12pt 的近方形色块按 centerY/centerX 对齐成"图例行/列"
     (距 plot ≤`LEGEND_ATTACH_GAP=40pt`)，连同同行的标签文本一起吸收。
  3. `expandToAxisLabels`：刻度标签带 = 纵轴左侧 `TICK_LABEL_BAND=55pt`；类别标签带 = plot 下方
     `CATEGORY_LABEL_BAND=30pt`；过滤条件 `isShortSingleLineText`：单行、高 ≤18pt、≤`MAX_LABEL_CHARS=64` 字符、
     不含句读标点(`[。，、；：！？;!?]`，**不含** ASCII 逗号/句点，否则 25,000.00 会被误杀)。
- 关键坑：标签带必须锚定在**增长循环后的 plot box**（不是被图例扩张后的 box），否则图例会把
  类别标签带"推"到类别标签下方 → 漏掉（-149 会出现）。
- 吸附到的 shape 通过 `markConsumedGroups` 标记，shape 与 text 一并从 pageContents 移除。

改动 2：`processors/FlowchartProcessor.java`
- 新增 `isStillOnPage()` 守卫：组的 shape 已不在 pageContents 时跳过。
  否则 BarChartProcessor 产出的截图会被 FlowchartProcessor 当"流程图"按同一区域再裁一次
  （实测 -28/-149 各产生 1 个孤儿 PNG，最终 bbox 被 Flowchart 版本覆盖）。这也是修复前就存在的隐患。

验证：
- `-28`：2 张图 → (151.9,99.2,455.5,261.4) 含 0~30 刻度+2021…2029E；(139.5,379.9,459.6,542.5) 含 0~250 刻度+2018…2023；
  `单位：万吨/亿元`、`数据来源`、正文仍为文本。
- `-149`：1 张图 → (98.7,393.9,483.3,592.5) 含 25,000.00…、2022/2023/2024年度、图例色块+文字；
  标题 `主要细分类型产品销售额`、`单位：万元` 仍为文本（符合口径①）。
- `-18.pdf`（单页）与 `p18_20.pdf` 饼图输出与改动前逐字节一致（未触碰饼图路径）。
- 单测：`BarChartProcessorTest(6)+CaptionProcessorTest(1)+ConsecutiveImageProcessorTest(6)+
