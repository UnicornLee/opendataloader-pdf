## 目录↔正文标题"相似性兜底匹配"（用户指定规则，已实现）

### 触发问题

`docs/pdf/202609031788435163969004864.pdf` 一级目录 `附錄一  －  購回授權之說明函件`（目录页第 2 页）
与正文页眉 `附錄一                  購回授權之說明函件`（第 11~14 页）**没匹配上**，
差异只有目录侧多出的 `－`（U+FF0D）。后者不在 `related_id` 解析范围内，于是 `附錄一` 的
`page_num` 停在印刷页 8、`related_id` 停在目录行自身的 item id。

### 根因

`CatalogBookmarkProcessor.matchBookmarkTitle`（主逻辑约 1878 行）只有两级判据：

```java
if (normalized.equals(normalizedTitle)) return MatchQuality.EXACT;
if (normalized.startsWith(normalizedTitle)) return MatchQuality.PREFIX;
return null;   // MatchQuality.CONTAINS 定义了但从未返回
```

`normalizeBookmarkText` 只删 `\s`，不删中间标点，所以"差一个 `－`"直接落空。

### 实现（用户给的规则）

- 新增 `MatchQuality.FUZZY`（枚举顺序 `EXACT, PREFIX, FUZZY, CONTAINS`；`ordinal()` 越小越优，
  所以相似匹配只在精确/前缀都失败后兜底）。
- `matchBookmarkTitle` 末尾追加 `isFuzzyTitleMatch(...)`。
- 判据：两条串必须有**非空的公共前缀**与**非空的公共后缀**，两侧中间"多出来的字符"之和 ≤
  `MAX_FUZZY_TITLE_GAP = 2`；再按差值套长度下限
  `FUZZY_MIN_LENGTH_SHORT = {0,4,8}` / `FUZZY_MIN_LENGTH_LONG = {0,5,10}`（下标 = 差值）。
- 辅助 `commonSuffixLength(a, b, prefixLength)`；所有 `(prefixLength, suffixLength)` 组合里取
  **最小差值**，用最小差值去套长度下限。

关于阈值归属：用户原文 2a 给"目录 4 / 内容 5"、2b 给"内容 4 / 目录 5"，二者自洽的读法是
**短的一侧 ≥ 4（差 1）/ ≥ 8（差 2），长的一侧 ≥ 5 / ≥ 10**，实现按此。

### 与用户原话的偏差（需用户确认）

用户说的是"把其中一侧拆成两段（A+B 相邻），另一侧 = A + 中间 + B"，即**必有一侧中间为空**。
实现按"两侧中间都要算进差值"实现，是原规则的**超集**：额外覆盖了
"1 个字符被替换"的情形（两侧中间各 1 个 → 差值 2，需要 ≥8/≥10 的长串）。
这个超集正好修好了 `20091006…` 里 `行`(U+884C) vs `行`(U+FA08 CJK 兼容表意文字) 的 self 书签。

### 待确认/遗留

1. 差值定义：现为"两侧中间多余字符之和 ≤ 2"（含 1 字符替换=2）。若要严格按原文（必有一侧中间为空）
   只需在 `isFuzzyTitleMatch` 里追加 `title.length()==prefix+suffix || itemText.length()==prefix+suffix`。
2. 生效范围：`matchBookmarkTitle` 有 3 个调用方——目录→正文解析、self 书签 `related_id` 解析、
   self 书签 `page_num` 修复；本次**三处都生效**。
3. 归一化只删 `\s`（ASCII 空白），**全角空格 U+3000 不删**；若正文用全角空格分隔标题，仍会不匹配。
4. `責任聲明 .... ii` 这类**罗马数字**目录条目依旧不参与正文解析（`parseOriginalPageNum` 非纯数字返回 0
   → `resolveCatalogBookmarkTarget` 提前 return），所以仍是 `page=1`。
