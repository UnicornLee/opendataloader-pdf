### "三源择一"是什么（用户问）

- 三份并存来源：`catalog_bookmarks`（目录页提取 + 补全 L2/L3）、`page_bookmarks`（正文页候选按模板/连续编号/字号/缩进构建的 ≤3 级树）、
  `self_bookmarks`（PDF 自带 outline）。
- `BookmarkQualitySelector.select(...)` 用 6 项指标给每源打分：effectiveCount、dupRatio、unlinkedRatio、strangeRatio、nonMonoRatio、invalidLinkRatio；
  `score = ln(1+effectiveCount) × (1−penalty)`，penalty 为五项比率之和（封顶 1）；penalty ≥ 0.5 淘汰。
- catalog 有"强胜率"保护：非 catalog 来源需 `score ≥ catalog×2.0` 才能赢（`CATALOG_STRONG_WIN_RATIO`）。
- 胜者写入 `"bookmarks"`，并把**胜者那个键从 JSON 删除**（避免内容重复），败者键保留以便排查。
- 本文件实测（A 生效后）：catalog 325 条 penalty=0.000 score=5.787，page 199 条 score=5.078（0.88x，未达 2.0x）→ **catalog 胜出**，
  self 为空被淘汰 → 最终 JSON 里 `bookmarks` = catalog 的 325 条树，`page_bookmarks`/`self_bookmarks` 保留，`catalog_bookmarks` 被移除。

## 第 248 页 3 个"单位：万元"挤在一起（已定位，修复中）

- 现象：4 个表格各带一个"单位：万元"（右上方），解析把**后 3 个合并成同一个 paragraph**（`[452.98,290.74,505.66,618.48]`，跨 327.7pt），下游渲染时挤在一起。
- 定位：插桩 `ParagraphProcessor`（`-DdbgParagraph=1` + `dbgUnits`/`PARA-PROB` 打印）→
  ```
  [PARA-PROB] result=0.0  prevBase=542.11 nextBase=383.45        ← 概率 0（行距/字号=15 倍，本该分段）
  [PARA] step=justify lines=3 [单位：万元@551.2][单位：万元@392.5][单位：万元@234.0]   ← 却已合并
  ```
- **根因**：`ParagraphProcessor.prejudgeParagraphs()`（第 356–379 行）的启发式分支 ——
  外层条件"右边界 ≈ 页面标准右边距 / 居中"+ "与下一行左缩进接近"命中后，内层只比较 `|margin - nextMargin| < 5`（**行距是否稳定**）与
  "下一行是否有缩进 `>10`"、"是否列表标签"，都不满足就落入 **else 兜底 `previousBlock.add(nextBlock.getLines())` —— 无任何绝对行距上限**。
  4 个跨表格的"单位：万元"间距恰好均匀（158.55/158.5/158.6），"间距稳定"反而成了合并理由。
  veraPDF 那条能挡住它的 `mergeLeadingProbability`（15 倍行距 ≫ 2.2 上限）在此路径上**根本没被调用**（prejudgeParagraphs 先返回 true 短路）。
- **已实施修复**（用户要求：另外，两行之间有表格/图片也要分段）：
  1. `processParagraphs(contents, width)` 收集的 `separators` 从"仅 LineArtChunk"扩展为 **LineArtChunk + TableBorder + Table + ImageChunk**；
     `hasLineArtBetween` 改名 `hasSeparatorBetween`、参数类型 `List<IObject>`（10 个方法参数同步改名 `lineArts`→`separators`）。
  2. 新增 `MAX_LINE_SPACING_RATIO = 3.0`：在 `prejudgeParagraphs` 判据链**最前面**加
     `if (prevFontSize > 0 && margin > MAX_LINE_SPACING_RATIO * prevFontSize) { 分段; }`。
