样本：`docs/pdf/201501131782598903817032205.pdf`（長江和記實業/長江實業 HK 招股书，193 页）。

  两横线之间的章节标题是**分段标题**，最长连续段 28 页（附錄四 P96–P123），占 14.5%；
  页脚页码逐页递增（序列匹配，不是相同文本）。

### 输出 JSON 实测（DebugSample 跑通，tmp_output/201501131782598903817032205.json）

- 警告文字（192/193 页）与页码：**已剥离**（JSON 里 count=0），符合预期。
- 章节标题：**190 页里有 184 页被当成页眉丢弃**（P4–P6 預期時間表、P12–P17 董事會函件、P56–P73 附錄一、
  P96–P123 附錄四 等）；只有 P2/P3/P53/P54 等"相邻页标题不同"的孤立页被保留 → 同一章节内前后不一致。

### 根因（代码定位）

`HeaderFooterProcessor`：
- `getIndexesOfHeaderOrFootersContents` 1-page style：相邻两页 `arePossibleHeadersOrFooters(a,b,1)` 命中即把两页加入 result；
  文本分支里 `Objects.equals(value1, value2)`（完全相同）就直接返回 true → **只要求"相邻两页相同"**，
  章节标题在章内所有相邻页都相同 → 形成长链被逐页剥离。
- 2-page style（2026-09-16 加的 chain/majority 收紧）同样会命中：章内 (p, p+2) 全等 → pairStarts 连续 → 全部是 chain 成员
  → `isChainedLongPattern` 成立 → 也会剥离。所以只收紧 1-page style 不够，守卫要落在两种 style 的**并集**上。
- 迭代 bookkeeping（`getNumberOfHeaderOrFooterContentsForEachPage`）只按"层级序号"推进，不区分"值"，
  所以"层级 2 的匹配页共 186 页（96%）"里混着 20 种不同标题 → **用"层级整体覆盖率"当判据无效**，
  必须按"值"统计覆盖率。

### 已给出的方案（等用户确认，未改代码）

- 方案 A（推荐）：给"文本值完全相同"的匹配加**值级覆盖率判据**——同一文本必须在 ≥ 阈值（默认 50%）的页面上出现，
  否则不算页眉/页脚；非"相同文本"的匹配（页码递增序列、bbox 相同）保持现状不受约束。
  本文件：警告文字 192/193 通过；章节标题最大 28/193 不通过 → 保留在正文。现有 5 个单测全部仍能通过。
- 方案 B（备选）：几何判据——页顶最上面两条横线（长度 ≥ 页宽约 50%、位于页顶 20% 内）夹出的区间内的内容不参与页眉判定。
- 已提醒的副作用：章节标题不再是 header 后，`TableBorderProcessor.checkNeighborTables` /
  `ListProcessor` / `LineArtProcessor` 里 `HeaderFooterProcessor.isHeaderOrFooter` 的三处判断会变化
  → 跨页表格 previousTable 链可能被章节标题打断，需要回归验证。

### 实施结果（用户已同意"方案 A + 阈值 50%"，已改完并验证）

- 单测：HeaderFooterProcessorTest 6/6、TableBorderProcessorTest 10/10 通过（共 16）。
- 真机（193 页）：章节标题缺失 0 页（改前 184 页缺失）；其中 119 页成为独立标题项、**71 页被并入本页首个段落**

- 归档：`docs/memory/2026-09-22-页眉误判章节标题为页眉-值级重复覆盖率判据与跨页表格链豁免.md`。
