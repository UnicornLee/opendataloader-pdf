`getValue().trim()` 结果可能为空字符串（PDF 里存在空文本行 / 空白 value 的行），此时 `length() - 1 == -1`，`substring(-1)` 抛 `StringIndexOutOfBoundsException: String index out of range: -1`。

- 方案 B（未采用）：prejudgeParagraphs 检测到空行提前 return，改动稍大、可能轻微改变段落合并行为。

## 根因总结

`ParagraphProcessor.prejudgeParagraphs` 对 trim 后为空文本的行直接 `substring(length - 1)`，空串时 index = -1 越界。

异常在并行流中的传播链：Loop 3（`DocumentProcessor.java:516` 的 `IntStream.range().parallel()` 段落处理）→ ForkJoinPool 把异常包成 `ExecutionException` → `DocumentProcessor.java:588` 外层 catch 解包后统一包成 `IOException("Parallel page processing failed (StringIndexOutOfBoundsException: null)")` → 用户看到的 message 就没了页码和具体行号。**并行模式下 message 无谓地丢失了子异常上下文，看 `-e`/printStackTrace 的完整栈才能定位**。

## 修复改动（方案 A）

`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/processors/ParagraphProcessor.java` 两行：

```java
// 286 行
String prevLastLineTextLastCh = prevLastLineText.isEmpty() ? "" : prevLastLineText.substring(prevLastLineText.length() - 1);
// 293 行
String nextFirstLineTextLastCh = nextFirstLineText.isEmpty() ? "" : nextFirstLineText.substring(nextFirstLineText.length() - 1);
```
