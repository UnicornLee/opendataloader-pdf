# 2026-08-11 — 书签长度过滤 + catalog 强胜率规则

## 任务背景
书签三来源（catalog / page / self）当前没有统一的长度过滤，目录里偶发掺入被编号正文/广告等超长文本条目；同时 `BookmarkQualitySelector` 在 catalog 存在时一律按优先级决胜（10% 相对差以内），catalog 即使质量不高也能赢。需要：
1. 长度过滤：L1/L2/L3 条目 `text.length() > 200` 时的级联删除规则
2. catalog 强胜率：其它来源必须 score ≥ catalog × 2.0 才能击败 catalog

## 改动清单

## 关键决策

### 删除语义（与用户拍板一致）
- L1.text > 200 → 只删该 L1，其它 L1 保留
- L1 下任一 L2.text > 200 → 该 L1 的全部 L2 子节点清空（保留 L1 本身）
- L2 下任一 L3.text > 200 → 该 L2 的全部 L3 子节点清空（保留 L2 本身）

> 之前描述"将整个二级目录删掉"歧义较大，用户补充后明确为"该父节点的整组 children 清空"，父节点本身保留。

### 长度阈值
- 用 `text.length() > 200`（不规整空白），与 `PageBookmarkProcessor#MAX_ENTRY_TEXT_LENGTH` 严格一致
- 用 `Bookmark.text` 原始文本判断，不去空白

### catalog 强胜率
- 阈值 2.0x（用户拍板，提议 1.5x 被否决）
- 逻辑：catalog 存在并通过淘汰线时，其它最强候选 `score / catalog.score ≥ 2.0` 才算赢；否则 catalog 默认保留
- 比值用 max(catalog.score, 1e-9) 防 0 除

### 现有 page 候选段过滤保留
- `PageBookmarkProcessor` 中 `cleanCandidates` / `isTocLikeGroup` 的长度过滤继续保留
- 它处理的是"构造期：编号正文被误识别为标题"的问题，与新过滤（处理构造后目录里的超长条目）互补，两者独立
