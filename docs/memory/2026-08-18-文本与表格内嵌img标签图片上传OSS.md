# 文本与表格内嵌 `<img>` 标签图片上传 OSS

- 时间：2026-08-18
- 任务：扩展 `JsonWriter#uploadImagesToOssAndUpdateMap`，在已支持 `item_type == "image"` 上传的基础上，新增对 `item_type == "text"` 和 `lattice_table / stream_table` 单元格内嵌 `<img src="...">` 标签的处理：解析文本/单元格中的 `<img>` 标签，将本地图片路径上传到 OBS 永久桶，用返回的 OSS URL 替换 `src`，并避免重复上传。
- 状态：已实现 + `mvn compile` 通过 + `DebugSample` 实跑验证成功上传并替换 `<img src>`，最终上传到 OSS 的 JSON 中 `src` 已是 OSS URL；PDF 文件已恢复。

## 目标（Goal）

- 解决 `item_type == "text"` 的 `content` 中以 `<img src='本地路径' style='...'>` 形式嵌入的图片无法被上传到对象存储的问题（参考 `tmp_output\hk_announcement_parse_all_1785127024065007121_1333488255283998720.json` 的样例）。
- 同时处理 `lattice_table` / `stream_table` 单元格 `text` 列表里出现的 `<img>` 标签（参考 `JsonWriter#generateJsonPageContentData` 的 `TableBorderCell` 序列化逻辑，line 995 也会生成 `<img src=...>`）。
- 同一张图片被多次引用时只上传一次。

## 用户偏好与约束（Constraints & Preferences）

1. 同一张图片在多个 `<img>` / `image` 项中出现时，只上传一次（通过缓存去重）。
2. 对象存储路径与现有 `image` 项保持完全一致：`public/{basicEnv}/{pulsarReceiveTopicName}_{businessId}/{imageFileName}`，桶为 `ossPermanentBucketName`。
3. 同一 `<img>` 标签内可能包含 `style` 等属性，替换 `src` 时必须**只改 src 字符串**，其它属性原样保留。
4. `<img>` 标签可能不止一个（多个标签或同一文本中出现多次）。
5. 本地图片路径必须位于 `outputFolder` 内才允许上传，避免被恶意或异常的 `src` 路径读取任意本地文件上传到 OSS（路径穿越风险）。
6. 远程 URL（`http://` / `https://` / `data:`）原样保留，不下载不上传。

## 前置事实（已核实）

- `JsonWriter#uploadImagesToOssAndUpdateMap` 原实现只处理 `item_type == "image"`，把 `content[0]` 当本地路径上传并替换。
- `JsonWriter#generateJsonPageContentData` 在 `TableBorderCell` 序列化时（line 995）会写出 `<img src='绝对路径' style='height: ...pt !important; width: ...pt !important;' />`，多个 `ImageChunk` 会拼接在单元格的 `text` 字符串里。
- `item_type == "text"` 的 JSON 结构有两种：
  - `content` 为 `List<Map>`，每个 `Map` 内嵌 `content: List<String>`（典型 heading / paragraph / text_chunk 分支）。
  - 个别分支（极少）`content` 直接是 `List<String>`。
- `lattice_table` / `stream_table` 的 `content` 是 `List<List<Map>>`，每个 `Map` 含 `text: List<String>`。
- `DebugSample` 已配置好 OBS（`DebugSample.java`，测试 PDF：`docs\pdf\202504151785127024065007121.pdf`），OSS 配置在 `customOptions` 内：`ossEndpoint=https://obs.cn-north-1.myhuaweicloud.com`、桶名 `stock-temp-bucket`（临时）/ `common-pdf-bucket`（永久）、`basicEnv=test`、`pulsarReceiveTopicName=pdf_parse_increment`、`businessId=123456789`、`ossDomainName=https://common-pdf-bucket.obs.cn-north-1.myhuaweicloud.com/`。
- OSS 上传成功后 `DocumentProcessor#processFileWithResult` 的 `finally` 会删除源 PDF，所以测试前必须备份。

## 已实现方案

### 改动 1：`JsonWriter.java` 的图片上传逻辑扩展
位置：`java\opendataloader-pdf-core\src\main\java\org\opendataloader\pdf\json\JsonWriter.java`

- 新增类常量：
  ```java
  private static final Pattern IMG_SRC_PATTERN = Pattern.compile(
          "<img\\b[^>]*?\\bsrc\\s*=\\s*(['\"])(.*?)\\1[^>]*?>",
          Pattern.CASE_INSENSITIVE | Pattern.DOTALL);
  ```
  捕获 `<img>` 标签，group 1 是引号，group 2 是路径。
- `uploadImagesToOssAndUpdateMap` 签名增加 `String outputFolder` 参数（写入处 `writeToCustomJson` 同步调整），用于路径校验。
- 引入内部类 `ImageUploadCache`：
  - `Map<String, String> pathToUrl`：本地路径 → OSS URL。
  - `Set<String> missingOrSkipped`：远程 / 越界 / 不存在的路径，避免重复打 warning。
- `uploadImagesToOssAndUpdateMap` 改为按 `itemType` 分发：
  - `"image"` → `uploadImageItemContent`（旧逻辑）。
  - `"text"` → `processTextItemContent`（新增）。
  - `"lattice_table"` / `"stream_table"` → `processTableItemContent`（新增）。
- 新增方法 `replaceImgSrcWithOssUrl(text, outputFolder, cache, obsClient, ossConfig)`：
  - 用 `Matcher.appendReplacement` / `appendTail` 替换 `src` 值；
  - 仅替换 group 2 部分，前后的 `<img`、引号、`style` 等属性保持原样；
  - 使用 `Matcher.quoteReplacement` 转义 `$` / `\`。
- 新增方法 `replaceImgSrcInStringList(List<Object>, ...)`：抽出文本和表格中共用的字符串列表替换逻辑，消除重复。
- 新增方法 `uploadImageIfNeeded(localPath, outputFolder, cache, ...)`：
  - 缓存命中直接返回；
  - 缺失/跳过集合中直接返回 `null`；
  - `isRemoteOrDataUrl` 拦截 `http://` / `https://` / `data:`；
  - `isPathUnderOutputFolder` 校验：把 `localPath` 和 `outputFolder` 都 `toAbsolutePath().normalize()` 后比较 `startsWith`，限制只能上传输出目录下的文件；
  - 文件不存在或越界则记录 `WARNING` 并加入 `missingOrSkipped` 集合；
  - 命中则生成 `public/{basicEnv}/{topic}_{businessId}/{fileName}` 的 objectKey，调用 `obsClient.uploadFile` 并缓存。
- 新增方法 `isRemoteOrDataUrl` 与 `isPathUnderOutputFolder`（私有静态）。
- 新增 import：`java.util.HashSet`、`java.util.regex.Matcher`、`java.util.regex.Pattern`。
- `writeToCustomJson` 中调用 `uploadImagesToOssAndUpdateMap(map, outputFolder, obsClient, ossConfig)` 同步传入 `outputFolder`。

## 关键决策（Key Decisions）

- **正则用 `\1` 反向引用**：保证开闭引号一致，避免 `<img src='...\">` 这种不对称情况误匹配。
- **路径校验必须落到 `outputFolder`**：防止恶意 PDF 文本中的 `<img src="/etc/passwd">` 等路径穿越。`normalize()` 用于消解 `..` 与 `.`。
- **缓存两类结果**：成功 URL 缓存避免重复上传；缺失/越界/远程的路径也缓存，避免重复打 warning 日志。
- **替换时只动 group 2**：`Matcher.start(0)` 到 `start(2)`、`end(2)` 到 `end(0)` 两段拼接保留 `<img` 标签名与 `style=` 等其它属性。
- **表格中 `ImageChunk` 已在 `JsonWriter#generateJsonPageContentData:995` 生成 `<img src>`**：本次同步处理表格单元格，文本与表格共用 `replaceImgSrcInStringList` helper，避免重复。
- **输出目录限制由 caller 传入**：`uploadImagesToOssAndUpdateMap` 改为接收 `outputFolder` 参数，不在 helper 内硬编码，便于后续调用方（如 `rebuildBookmarksFromJson`）按需调整或跳过。

## 风险与已知限制

- **未覆盖单元测试**：code-review 列出 MEDIUM，需要后续补多个 `<img>` / 缺失文件 / 嵌套文本 / 表格 / 单双引号 / 远程 URL / 路径穿越 7 类用例。
- **图片 object key 仍以 `imageFileName` 命名**：跨 PDF 同名图片会覆盖（既有逻辑，code-review LOW）。
- **`outputFolder` 为空时跳过路径校验**：`isPathUnderOutputFolder` 在 `outputFolder` 为空时直接返回 `true`，避免误判；安全上稍有让步。
- **当前 `text` 内容结构处理了 Map 与 String 两种形态**，但未对 `cellMap` 的非 `text` 字段做处理；与现有写入逻辑保持一致。
- **路径校验依赖 `normalize()`**：在 Windows 上对符号链接、UNC 路径未做特殊处理；测试环境无相关 PDF，未触达该边界。
