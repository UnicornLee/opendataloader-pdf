# 中文序号 "1、" 与上一个段落合并的根因分析与修复

**日期**：2026-08-12
**分支**：valueonline-20260722
**问题文件**：`docs/pdf/202303251679660111823147-7.pdf`（第 2 页）

---

## 现象

PDF 第 2 页包含：

```
产投资风险、环保安全风险、汇率波动风险、新业务投资风险。具体如下：
1、前期收到的重大订单终端需求下降的风险
2021 至 2022 年，公司陆续收到美国某大型制药公司的某小分子创新药相关
...
2、服务的创新药退市或被大规模召回以及终端市场需求波动风险
...
3、固定资产投资风险
...
```

解析后 `1、前期收到的重大订单终端需求下降的风险` 与 `…具体如下：` 被合并到
同一个 `source_type: heading` 的 item 中，但 `2、服务的…` 和 `3、固定…` 都正确
独立成 heading。

期望：`1、前期…` 应当是单独的段落（heading），与 `2、…` / `3、…` 行为一致。

---

## 根因

两处缺陷叠加：

### 缺陷 1：`BulletedParagraphUtils.isLabeledLine()` 不识别中文序号

文件：`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/utils/BulletedParagraphUtils.java`

仅识别西文模式：
```java
BULLET_REGEXES.add("^\\d+[\\.\\)]\\s+.*");   // 1. xxx / 1) xxx
```

没有 `^\\d+、.*`（中文顿号）或 `^\\d+，.*`（中文全角逗号），所以
`1、前期…` 不被认为是带标签的列表项。

`ParagraphProcessor.areLinesOfParagraphsWithLeftAlignments()`（行 426-428）
本来对"带标签的下一行"会直接 `return false` 阻止合并；因为 isLabeledLine
返回 false，这条保护被绕过。

### 缺陷 2：`GlobalConstant.SENTENCE_ENDING_PUNCTUATION` 不含全角冒号

文件：`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/custom/constants/GlobalConstant.java:8`

```java
public static final List<String> SENTENCE_ENDING_PUNCTUATION = Arrays.asList(
    ".", "。", "！", "！", "？", "？");
```

`ParagraphProcessor.prejudgeParagraphs()`（行 325-330）靠这个集合判断前置行
是否以"句末标点"结尾，从而在合适几何条件下强制断行。当前置行是
`…具体如下：`（以 `：` 结尾）时，因为 `：` 不在集合里，强制断行条件不满足。

最后落入 else 分支（行 334-336）→ 把 `1、前期…` 合并进上一个 TextBlock。

### 为什么 item 4、6 不出问题？

- Item 4 前置段落 `…经营及业绩的影响。` 以 `。` 结尾 → `。` 在
  SENTENCE_ENDING_PUNCTUATION → 强制断行
- Item 6 同理
- Item 2（`1、前期…`）前置行以 `：` 结尾 → 不在集合里 → **错误合并**

---

## 修复方案

仅采用 **方案 A**：在 `BulletedParagraphUtils.BULLET_REGEXES` 增加中文序号模式。

```java
BULLET_REGEXES.add("^\\d+[\\.\\)]\\s+.*");   // 现有：1. xxx / 1) xxx
// 新增：中文顿号（1、xxx）
BULLET_REGEXES.add("^\\d+、.*");
// 新增：中文全角逗号（1，xxx）
BULLET_REGEXES.add("^\\d+，.*");
```

**为什么选 A**：
- 与现有西文模式一致
- 与 `PageBookmarkProcessor` 已经在用的 `CHINESE_NUMBERS_WITH_COMMA_1_TO_100`
  （"一、"）语义一致
- 命中后走 `isLabeledLine` → `areLinesOfParagraphsWithLeftAlignments` 直接
  `return false` → 不合并
- 风险可控：仅在行首生效，不会误伤正文里的 "1、"

**未采用 B（把 `：` 加入 SENTENCE_ENDING_PUNCTUATION）的原因**：
- `：` 是引介标点而非句末标点
- 改动面更大，可能影响其他布局

## 改动清单

只改 1 个文件，3 行新增 + 4 行注释：

`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/utils/BulletedParagraphUtils.java`

```diff
         BULLET_REGEXES.add("^\\d+[\\.\\)]\\s+.*");
+        // Chinese enumeration mark (、, U+3001): e.g. "1、风险说明". Unlike the
+        // western counterparts above, Chinese typography rarely inserts a space
+        // after the separator, so this pattern deliberately allows zero or more
+        // whitespace chars after the separator.
+        BULLET_REGEXES.add("^\\d+、.*");
+        // Chinese full-width comma (，, U+FF0C): e.g. "1，风险说明".
+        BULLET_REGEXES.add("^\\d+，.*");
```
