## 根因 / 定位过程

### 1. 先确认最终 `bookmarks` 到底来自哪个来源

JSON 顶层只有 `self_bookmarks` / `page_bookmarks` / `bookmarks` 三个键——`catalog_bookmarks` 被移除 → 说明 catalog 被选为胜出源。再比对 `page_bookmarks` 的内容：里面是正文标题（如「一、补充说明发行人…」），与最终树不一致 → **确认最终树就是 catalog 管线的产物**，用户的判断成立。

### 2. 目录页的真实数据（决定性的第一手证据）

从 JSON 的目录页 items 直接提取候选项的 `x0`（leftX）：

| 条目 | leftX |
|---|---|
| `目录`、`一、业务与技术`、`二、…`、`三、…`、`四、…` | 89.88 |
| `问题1` … `问题11` | 113.9 |

缩进差 **24pt，远超聚类阈值**。这说明「按缩进聚类」这一步**本身是正确的、没有出错**，问题只能出在聚类**之后**的纠偏步骤。（这一点很关键：它把排查范围从「聚类/阈值」一下子收缩到了「层级纠偏」。）

### 3. 代码链路逐环核对（`CatalogBookmarkProcessor`）

- `assignLevels` 的顺序是：Step 1 `clusterByLeftX` → Step 2 用聚类结果赋初始层级 → Step 3 `correctLevelsByPrefix` → Step 4 clamp(1..3) 写回 `level`。
- Step 2 的结果是**正确**的：113.9 全部落入 cluster 1 → 所有 `问题1..11` 初始都是 level 2。
- **元凶是 Step 3 `correctLevelsByPrefix` 的第 1 步**：它把「开头 / 结尾的**无前缀**条目强制为 L1」。
- 而 `问题N.` 这种前缀在 `BookmarkPrefixClassifier` 中**不被识别**（`classify` 返回 `null`，`prefixType == null`）：
  - `问题1..9` 夹在 `一、/二、/三、/四、` 这些**有前缀**的一级之间 → 不满足「结尾无前缀」→ 保留 level 2 → 正确嵌套；
  - `问题10/11` 位于**最后一个有前缀一级 `四、` 之后** → 被判为「结尾无前缀」→ 强行 `levels[i] = 1` → 变成一级。
- 追加结论：这个降级**无法被后续步骤救回**。Step 2「同前缀连续段统一层级」是按当前 `levels` 统计**众数**的，而 Step 1 已经把这两个位置改成了 1，众数于是也是 1——污染发生在统计之前。

### 4. 验证手段（OCR 不可达时的替代路径）

沙箱内 OCR 端点（`paddleUrl`）不可达，跑不了完整 `OpenDataLoaderPDF.processFile`。改用**纯 JSON 路径**：

```java
CatalogBookmarkProcessor.extractCatalogBookmarksFromJson(data, config)
```

它与 `rebuildBookmarks` 复用同一条书签管线（catalog 检测 + 层级纠偏 + 来源选择），只是从已有 JSON 重算书签、不需要 OCR。再写一个临时 `DebugCatalog` 打印每条候选的 `leftX / level / prefixType` 逐条确认。验证完即删除临时文件。

## 改动清单

`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/processors/CatalogBookmarkProcessor.java` → `correctLevelsByPrefix` 第 1 步：

```java
// 改前：开头 / 结尾的无前缀条目一律强制为 L1
for (int i = lastPrefixIndex + 1; i < n; i++) {
    levels[i] = 1;
}

// 改后：只有当该条目本身就位于一级左边界（即无缩进）时才强制为 L1；
//       有缩进的条目保留 clusterByLeftX 算出的层级。
double l1LeftX = candidates.stream().mapToDouble(c -> c.leftX).min().orElse(0.0);
for (int i = lastPrefixIndex + 1; i < n; i++) {
    if (Math.abs(candidates.get(i).leftX - l1LeftX) < 2.0) {
        levels[i] = 1;
    }
}
```

「开头那半段」（`firstPrefixIndex` 之前的无前缀条目）同样加了该判断。容差取 `2.0`，与该文件既有注释里「L1 位于最小 leftX ±2 之内」的说法保持一致。

## 关键决策

- **候选方案 A**：在 `BookmarkPrefixClassifier` 中注册 `问题#.` / `问题#、` 前缀，让 `问题*` 拥有 `prefixType`，从而走前缀连续性逻辑自动归到 L2。更通用，但会扩大影响面——`isBookmarkCandidate` 等其它调用点会跟着变化，跨文档回归风险大。
- **候选方案 B**：Step 1 对 `cluster > 0`（有缩进）的条目一律不降级。语义接近 C，但不如 C 精确。
- **采用方案 C（用户确认）**：只修正「纠偏步骤」，不触碰分类器 → 改动最小、回归面最小。
- **已知遗留（未处理）**：如果某文档存在「既不是已识别前缀、又与一级完全同缩进」的尾缀条目，仍会被当作 L1。这类排版很罕见，先不引入额外判据。
