## 定位过程

### 阶段 1：先找到"目录 ↔ 正文"的匹配入口

`resolveCatalogBookmarkTargets` → `resolveCatalogBookmarkTarget`（`CatalogBookmarkProcessor`）
遍历所有"非目录页"的 `text` item（`isParagraphOrHeadingItem`），对每条 item 调
`matchBookmarkTitle(normalizedTitle, itemText)`，按 **页码距离优先、匹配质量次之** 选最优目标。

`matchBookmarkTitle`（1887 行）当时只有两级：

```java
String normalized = normalizeBookmarkText(itemText);
if (normalized.equals(normalizedTitle)) return MatchQuality.EXACT;
if (normalized.startsWith(normalizedTitle)) return MatchQuality.PREFIX;
return null;
```

`normalizeBookmarkText`（1965 行）只做 `text.replaceAll("\\s+", "").trim()` —— **只删空白**。
枚举里虽然定义了 `CONTAINS`，但**从来没有返回过**，即"相似性匹配"这一档根本不存在。

所以两级判据全部落空 → 返回 `null`。

> 解析按"离印刷页 8 最近"取值，最终落到第 11 页（也正是 `附錄一` 真正的起始页）。

### 阶段 4：用户给出的规则与澄清点

> a. 目录从中间某一位置拆成两端，第一段刚好是内容的开头，第二段刚好是段落的结尾，
> 中间差不到两个字符（忽略空格），则认为匹配。差一个字符的话，目录的字符总长度不能小于 4，
> 内容的字符总长度不能小于 5。差两个字符的话，目录的字符总长度不能小于 8，内容的字符总长度不能小于 10。
> b. 或者内容从中间某一位置拆成两端，第一段刚好是目录的开头，第二段刚好是目录的结尾，
> 中间差不到两个字符（忽略空格），则认为匹配。差一个字符的话，内容的字符总长度不能小于 4，
> 目录的字符总长度不能小于 5。差两个字符的话，内容的字符总长度不能小于 8，目录的字符总长度不能小于 10。

把 a/b 两条并排看，能读出一个**自洽的规律**：被拆开（也就是"中间有富余字符"）的那一侧阈值更小。

| 差值 | 短的一侧 ≥ | 长的一侧 ≥ |
|---|---|---|
| 1 个字符 | 4 | 5 |
| 2 个字符 | 8 | 10 |

用本文的例子校验：a 侧多一个 `－` → a 是被拆开/有富余的一侧（长度 13），b 无富余（长度 12）；
差值为 1，套"短≥4/长≥5" → `12 ≥ 4` ✅、`13 ≥ 5` ✅ → 应当匹配。

### 阶段 5：把"差"的度量方式定下来

a/b 两条规则合起来只覆盖"**必有一侧中间为空**"（一侧正好是 A+B 相邻两段）。
实现时选择了更一般（也更保守）的度量：**两侧中间的富余字符数之和**。

```
gap = (len(title) - prefix - suffix) + (len(itemText) - prefix - suffix)
```

- 一侧中间为空时，`gap` 就等于另一侧中间的字符数 → 与用户原文完全一致；
- 额外覆盖"中间 1 个字符被替换"（两侧各富余 1 个 → gap = 2 → 需长串 ≥ 8/≥ 10 才放行），
  这个超集恰好修好了 `20091006…` 里 `行`(U+884C) 与 `行`(U+FA08 CJK 兼容表意文字) 的自带书签（见验证）。

实现里对所有 `(前缀长度, 后缀长度)` 组合取**最小 gap**，再用最小 gap 去套长度下限，
并要求"前缀非空、后缀非空"，且后缀不得与前缀重叠。

---

## 根因

1. **匹配器只有"完全相等"和"正文以目录标题开头"两档**（`matchBookmarkTitle`），
   枚举里预留的 `CONTAINS` 从未返回，**没有任何相近判定**；
2. `normalizeBookmarkText` 只删空白、不删中间标点，所以
   `附錄一 － X` 与 `附錄一 X`、`行` 与 `行`（兼容表意文字）这类**仅差一个中间字符**的标题必然失配；
3. 失配后 `resolveCatalogBookmarkTarget` 不做兜底，书签保留
   `resolvePageIndex(印刷页)+1` 的初始值，`related_id` 保留目录条目自身的 id —— 表面上"有页号"，
   实际指向错误页面，掩盖了问题。

## 修复实施

文件：`java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/processors/CatalogBookmarkProcessor.java`

### 1. 常量（143-148 行）

```java
private static final int MAX_FUZZY_TITLE_GAP = 2;
// 下标 = 差值（1 / 2）；短的一侧用第一个数组，长的一侧用第二个
private static final int[] FUZZY_MIN_LENGTH_SHORT = {0, 4, 8};
private static final int[] FUZZY_MIN_LENGTH_LONG  = {0, 5, 10};
```

### 2. 匹配质量加一档（1973 行）

```java
private enum MatchQuality { EXACT, PREFIX, FUZZY, CONTAINS }
```

比较用的是 `quality.ordinal()`（越小越优），把 `FUZZY` 插在 `PREFIX` 之后、`CONTAINS` 之前，
保证**相似匹配只在精确/前缀都失败后兜底**。

### 3. 挂到匹配器末尾（1898-1900 行）

```java

    return MatchQuality.FUZZY;
}
return null;
```

### 4. 相似判据（1921-1948 行）

```java
private static boolean isFuzzyTitleMatch(String title, String itemText) {
    int minLength = Math.min(title.length(), itemText.length());
    if (minLength < 2) return false;
    int shortestGap = Integer.MAX_VALUE;
    for (int prefixLength = 1; prefixLength < minLength; prefixLength++) {
        if (title.charAt(prefixLength - 1) != itemText.charAt(prefixLength - 1)) break;  // 公共前缀必须连续
        int suffixLength = commonSuffixLength(title, itemText, prefixLength);
        if (suffixLength == 0) continue;                                                 // 后缀必须非空
        int gap = (title.length() - prefixLength - suffixLength)
                + (itemText.length() - prefixLength - suffixLength);
        if (gap > 0 && gap < shortestGap) shortestGap = gap;
    }
    if (shortestGap > MAX_FUZZY_TITLE_GAP) return false;
    int shorter = Math.min(title.length(), itemText.length());
    int longer  = Math.max(title.length(), itemText.length());
    return shorter >= FUZZY_MIN_LENGTH_SHORT[shortestGap]
            && longer >= FUZZY_MIN_LENGTH_LONG[shortestGap];
}

// 1954 行：公共后缀，且不与前缀重叠
private static int commonSuffixLength(String a, String b, int prefixLength) {
    int maxLength = Math.min(a.length(), b.length()) - prefixLength;
    int suffixLength = 0;
    while (suffixLength < maxLength
            && a.charAt(a.length() - 1 - suffixLength) == b.charAt(b.length() - 1 - suffixLength)) {
        suffixLength++;
    }
    return suffixLength;
}
```

`shortestGap` 保持 `Integer.MAX_VALUE` 时（找不到任何对齐）在比较处即返回 `false`，不会越界索引数组。

### 5. 生效范围

`matchBookmarkTitle` 有 **3 个调用方**，本次**三处同时生效**：

1. `resolveCatalogBookmarkTarget`：目录条目 → 正文页/`related_id`（本次目标）；
2. `resolveSelfBookmarkRelatedId`：自带书签 → 同页 item 的 `related_id`；
3. `repairSelfBookmarkRelatedPageNums`：自带书签 `page_num` 为 0 时的区间内修补。

内容路径（`extractCatalogBookmarks`）不涉及标题匹配，未改。

## 与用户原话的偏差（已向用户说明，待其确认）

用户原文的 a/b 两条只覆盖"**必有一侧中间为空**"（该侧正好拆成相邻两段）。
实现按"**两侧中间富余字符之和 ≤ 2**"落地，是原文的**超集**，额外允许"中间 1 个字符被替换"
（两侧各富余 1 个 → gap = 2，须满足长串 ≥ 8 / ≥ 10）。若要严格回到原文，只需在
`isFuzzyTitleMatch` 里追加一个条件：

```java
|| title.length() == prefixLength + suffixLength
|| itemText.length() == prefixLength + suffixLength
```

其余待确认点：

1. 差值定义：保持"两侧之和"，还是收紧为原文；
2. 生效范围：是否只允许对"目录 → 正文"生效（现在三处调用方都生效）；
3. "忽略空格"只覆盖 ASCII 空白（`\s`），**全角空格 U+3000 不删**，是否要补上；
4. 两个长度下限数组目前是硬编码常量，是否需要做成 `Config` 可配（现有
   `catalogBookmarkMinTocLines` / `catalogBookmarkMinTocRatio` 是可配的）。

## 附带发现与遗留

1. **罗马数字目录条目依旧不做正文解析**：`parseOriginalPageNum('ii')` 返回 0，
   `resolveCatalogBookmarkTarget` 见 `catalogHint <= 0` 直接 return，所以 `責任聲明` 仍是 `page_num=1`
   （正文其实在第 3 页）。相似匹配救不了它，需要单独处理"罗马数字 hint"。
2. `related_id` 的语义混合：目录条目解析成功后才指向正文 item，失败时残留"目录页自身 item id"，
   排查时容易误读为该 id 有意义（本次就是靠 `related_id=3` 一致才判断出三个 `附錄` 都没解析成功）。
3. 模糊匹配放宽后，理论上存在"正文里恰以标题开头、并以标题结尾、中间只差 ≤2 字"的误匹配；
   本次 35 个文档未出现，但语料有限，后续应关注。
4. 内容路径 `extractCatalogBookmarks` 无 main 调用方；本次修复只覆盖 JSON 路径（生产路径）。
