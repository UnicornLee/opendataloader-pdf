# opendataloader-pdf 任务记忆 — 2026-08-16（公式 OCR 与 JSON 输出重构 + 代码审查修复）

- 时间：2026-08-16
- 任务：在 2026-08-15 的 LineArtProcessor 性能优化基础上，继续完成公式/线条图像 OCR 双路径、JSON 输出稳定性、OSS 上传与书签重建等实现，并进行代码审查、注释翻译、LOGGER 中文化移除及小 bug 修复。

## 目标（Goal）

- 解决扫描件/公式密集 PDF 在启用 `paddleUrl` 时解析极慢的问题：把“每组串行 OCR”改造成“少组并行 OCR + 多组整页 OCR”。

- 代码可维护性：将修改过的类中的中文注释/Javadoc、中文 LOGGER 日志全部改为英文；清理未使用导入；修复明显的 NPE/资源泄漏隐患。

## 详细改动

### 1. `OpenDataLoaderPDF.java`

**shutdown 异常安全**

- 原实现直接链式调用 `HybridClientFactory.shutdown()`；一旦第一个失败，后续 Paddle 资源无法释放。
- 新增 `shutdownQuietly(String name, Runnable shutdown)`：每个 shutdown 独立 try/catch，失败时记录 `WARNING` 并继续清理其余资源。
- 调用顺序：
  1. `HybridClientFactory.shutdown()`
  2. `PaddleOcrClient.shutdown()`
  3. `PaddleOcrProcessor.shutdown()`

**Javadoc**
- 更新 `shutdown()` 说明，明确释放 hybrid mode 后端与 Paddle OCR 的 HTTP 线程池。

### 2. `DocumentProcessor.java`

**常量与工具方法**

- 新增 `OCR_FALLBACK_GARBAGE_RATIO_THRESHOLD = 0.5`（从文件末尾移到类顶部）。
- 新增 `OCR_FALLBACK_RENDER_DPI = 300.0f`。
- 新增 `formatElapsed(long nanos)`：把纳秒格式化为 `X s` / `X minutes Y seconds` / `X hours Y minutes Z seconds`，用于最终耗时日志。
- 新增 `modeOfValues(double[] values)`：对非零值取众数，用于缺失页面尺寸回填。

**每页独立尺寸（mixed-size/rotation PDF 修复）**

- 旧逻辑：取第 0 页 `width/height` 用于整份文档。
- 新逻辑：
  1. 遍历所有页取真实 `width/height`，缺失记为 `0.0`。
  2. 用众数回填缺失的宽/高；若某页宽高同时为 0，记录 `WARNING`。
- 影响路径：
  - OCR fallback 判断与渲染。
  - `StreamTableProcessor.processStreamTables`。
  - `ParagraphProcessor.processParagraphs`。
  - `LineArtProcessor.processLineArtGroups` 调用时传入 `pageWidths[pageNumber]` / `pageHeights[pageNumber]`。

**计时笔误修复**

- 原：`long extractionNs = to - startTime;`（`to` 未定义，编译错误）。
- 改为：`long extractionNs = t0 - startTime;`。
- 日志中的耗时改用 `formatElapsed(...)` 输出人类可读格式。

**OSS 上传后删除源文件**

- 中文注释改为英文。
- 仅当 `customOutput.isOssUploadSuccess()` 为 true 时才尝试删除原始 PDF。

**公式识别入口调整**

- 在调用 `LineArtProcessor.processLineArtGroups` 前判断 `paddleEnabled`：
  - 若未启用，打印英文 INFO 日志：`"No OCR service configured; skipping formula recognition to avoid false positives."`
  - 若启用，继续计算线条图像候选数并调用（不再因候选数多就放弃，上限控制下沉到 `LineArtProcessor`）。
- 调用签名从 4 参数扩展为 7 参数：新增 `inputPdfName`、`pageWidths[pageNumber]`、`pageHeights[pageNumber]`。

**其他注释翻译**

- 排序、流式表格识别、ShapeChunk 分组等中文注释译为英文。

### 3. `LineArtProcessor.java`

**整体策略（Two-tier OCR）**

- 移除旧常量：
  - `FORMULA_RECOGNIZE_MAX_COUNT = 5`（每页上限已不在此处控制）。
  - `PADDLE_MAX_RETRIES` / `PADDLE_RETRY_SLEEP_SECONDS`（重试已下沉到 `PaddleOcrClient`）。
  - `MIN_LINE_ART_OVERLAP_PERCENT`（改用 `BoundingBoxGroupUtils.hasSignificantOverlap`）。
- 新增常量：
  - `PAGE_LEVEL_OCR_THRESHOLD = 2`：≤2 个候选走并行逐组 OCR，>2 走整页 OCR。
  - `FORMULA_IOU_THRESHOLD = 0.3`：整页 OCR 结果与候选区匹配的 IoU 阈值。
  - `PAGE_LEVEL_RENDER_DPI = 200.0f`：整页渲染 DPI。
  - `PAGE_LEVEL_ENTRY_IOU_THRESHOLD = 0.5`：整页 OCR 未匹配到的 LaTeX 条目 fallback 时与 pageContents 元素匹配的 IoU 阈值。
  - `DEFAULT_FORMULA_FONT_SIZE = 12.0`。

**`processLineArtGroups` 流程**

1. 按 `topY` 降序排序（保证从上到下扫描）。
2. `scanAndMerge(...)`：单次扫描同时完成合并与候选收集；所有 `LineArtChunk` 都会合并（装饰线、分隔线也会合并成 `ImageChunk`），OCR 过滤延后。
3. 若 `candidates` 为空则直接返回。
4. Paddle 启用时：
   - 候选数 ≤2 → `applyGroupLevelOcr`
   - 候选数 >2 → `applyPageLevelOcr`
5. Paddle 禁用时：合并后的 `ImageChunk` 保留在 `pageContents` 中，不再提前 `return` 原样返回（修复 `LineArtProcessorTest` 失败）。

**新增核心方法**

| 方法 | 作用 |
|---|---|
| `scanAndMerge` | 单次扫描合并重叠 `LineArtChunk`，返回候选列表。 |
| `applyGroupLevelOcr` | 通过 `PaddleOcrClient.submitOcrTask` 并发提交所有候选，OCR 成功且识别为公式则替换为 `TextChunk`，否则撤销合并。 |
| `applyPageLevelOcr` | 渲染整页 → 单次 OCR → `buildOcrEntries` 转坐标 → IoU 匹配候选区；未匹配的 LaTeX 条目走 `applyPageLevelEntryFallback`。 |
| `applyPageLevelEntryFallback` | 对未匹配 LaTeX 条目，在 `pageContents` 中按 IoU>0.5 找可替换对象，否则追加为 `CustomSemanticParagraph`。 |
| `replaceMergedChunkWithGroup` / `replaceMergedChunkWithObject` / `replaceMergedChunkWithGroupOrdered` | 基于对象身份 `==` 在 `pageContents` 中定位并替换合并后的 `ImageChunk`。 |
| `restoreAllGroups` | 所有失败路径调用，保证“OCR 失败则还原原文”。 |
| `buildOcrEntries` | 把 Paddle 像素坐标转 PDF user units，标记 `isLatex`。 |
| `findBestIouMatch` | 最佳 IoU 匹配，避免一个 OCR entry 被重复匹配。 |
| `renderPageToImage` | 用 PDFBox `PDFRenderer.renderImageWithDPI` 生成临时 PNG。 |
| `drainFuture` | 带 120 秒超时的 `Future.get`，处理中断/执行异常。 |

**临时文件清理**

- `applyPageLevelOcr` 把整页渲染后的 `rendered.imageFile.delete()` 放在 `finally` 中，避免成功/失败路径泄漏临时 PNG。

**内部数据结构**

- `CandidateRange`：group / union bbox / imageChunk。
- `OcrEntry`：PDF 坐标 bbox / isLatex / text / fontSizeHint / consumed 标记。
- `RenderedPage`：临时文件 / 像素宽高。

**公式字体大小**

- 优先取组内 `CustomSemanticParagraph` 的最大字体；若不存在，使用 `union.getHeight() / 2.0` 或 `DEFAULT_FORMULA_FONT_SIZE`。

### 4. `PaddleOcrProcessor.java`

**OkHttp 客户端优化**

- 移除硬编码 `DEFAULT_PADDLE_URL`。
- `PADDLE_CLIENT` 改为 `buildPaddleClient()` 构建：
  - 自定义 daemon 线程池 `paddle-okhttp-N`。
  - `Dispatcher`：`maxRequests=64`，`maxRequestsPerHost=16`。
  - `ConnectionPool(32, 5, TimeUnit.MINUTES)`。
  - `retryOnConnectionFailure(true)`。
- `getPaddleResponse(...)` 现在要求调用方必须传入非空 `paddleUrl`，否则抛 `IllegalArgumentException`。

**资源关闭**

- 新增 `shutdown()`：关闭 dispatcher 线程池（等待 5 秒，超时强制 shutdownNow）并清空连接池。
- 在 `OpenDataLoaderPDF.shutdown()` 中调用。

**日志与注释**

- Paddle response 日志从 `INFO` 降为 `FINE`，避免大 JSON 刷屏。
- `convertBase64ToImage` 的中文 Javadoc/注释全部译为英文。
- `main(...)` 方法保留本地中文路径调试代码，**未修改**（按用户要求排除）。

### 5. `JsonWriter.java`

**导入与类结构**

- 新增 `ByteArrayOutputStream`。
- 移除未使用的 `INode`、`SemanticNode` 导入（代码审查后清理）。

**`writeToCustomJson` 重构**

- `url` 字段读取：先处理 `config != null && config.getCustomOptions() != null`，避免 NPE（2026-08-16 修复）。
- 每页序列化改为“独立内存缓冲”模式：
  1. 为每页创建独立 `ByteArrayOutputStream` 与 `JsonGenerator`。
  2. 调用 `writePageToGenerator` 生成完整页面对象。
  3. 成功后用 `jsonGenerator.writeRawValue(pageJson)` 拼入主流。
  4. 异常时记录 `WARNING` 并回退到 `placeholderPageJson(pageNumber + 1)`，保证 `data` 数组长度与 PDF 页数一致、页码连续。
- 文档级 metadata（`SerializerUtil.setElementMetadata`）仅在所有页序列化结束后清除一次，防止循环内清除导致后续页 enrichment 字段丢失。

**新增/拆出方法**

| 方法 | 作用 |
|---|---|
| `writePageToGenerator` | 在独立 `JsonGenerator` 上写完整页面对象（page_index / width / height / margins / items）。 |
| `generateJsonPageContentData` | 原内联的 items 序列化逻辑提取，处理 heading/list/caption/TOC/text/paragraph/table/image 等类型。 |
| `flattenHeaderFooterContents` | 仅展开页面中第一个 `SemanticHeaderOrFooter`，把其真实内容放回流中；后续 header/footer 保留原样。 |
| `placeholderPageJson` | 用 Jackson `ObjectMapperHolder` 生成 `{page_index, is_ocr, items: []}`，替代原来的字符串拼接。 |

**OCR 检测 JSON（`_ocr.json`）**

- `writeOcrDetectionJson`：扫描 `data` 每页，满足“items≤4、无表格、有图片、某图片高度/页高>0.8”时标记 `is_ocr=true` 并收集。
- 命中页汇总后写出 `<pdfname>_ocr.json`；无命中页跳过，避免空文件。
- `business_id` / `extend` 从 `config.customOptions` 读取，缺失保持向后兼容。

**图片上传与清理**

- `uploadImagesToOssAndUpdateMap`：遍历 JSON 的 image 项，上传到 OSS 永久桶并替换 `content[0]` 为 OSS URL。
- `buildJsonObjectKey` / `buildJsonObjectKeyForRebuild`：构造上传到临时桶的 object key。
- `resolveOcrJsonLocalPath`：解析 `_ocr.json` 本地路径，不存在返回空字符串。
- `cleanupLocalFiles`：上传成功后保留 `_ocr.json`，删除输出目录下与当前 PDF 相关的其他生成文件及图片目录。

**书签重建**

- `rebuildBookmarksFromJson`：从现有 JSON 读取 `self_bookmarks`，复用目录识别/页面书签抽取/质量选择流水线，重新生成 `catalog_bookmarks` / `page_bookmarks` / `bookmarks`。
- `resolveSelfBookmarkRelatedIds` / `repairSelfBookmarkRelatedPageNums`：修复 `self_bookmarks` 的 `related_id` 与 `page_num=0` 问题。
- `getItemFirstLineText` / `getItemFullText`：JSON item 文本辅助，`getItemFullText` 使用 `SmartTextJoiner` 按规则拼接。

**OSS 配置封装**

- 新增私有静态内部类 `OssUploadConfig`：
  - `fromCustomOptions(Config)`：校验 9 项完整配置（含永久桶）。
  - `fromCustomOptionsForJsonUpload(Config)`：校验 8 项（不含永久桶），用于仅重建 JSON 场景。
  - `getTempDomainName()`：把域名中的永久桶名替换为临时桶名。

**注释与日志**

- 所有中文注释/Javadoc 译为英文。
- 关闭 OBS client 时日志带上异常类型与堆栈。

## 关键决策（Key Decisions）

1. **合并行为不依赖 Paddle**：`scanAndMerge` 始终执行，装饰性线条图像也会合并为 `ImageChunk`；OCR 仅在 Paddle 启用时发起。这样无 OCR 时输出更紧凑，也符合 `LineArtProcessorTest` 的期望。
2. **整页 OCR 策略阈值 = 2**：大多数公式页只有 1~2 个公式；超过 2 个往往意味着整页公式/段落线，整页 OCR 更划算。
3. **单页序列化隔离**：每页先写独立 buffer，异常只影响该页，避免一份 PDF 中某一页处理失败导致整份 JSON 损坏。
4. **占位页用 Jackson 生成**：避免字符串拼接带来的转义/格式风险。
5. **临时 PNG 必须清理**：`applyPageLevelOcr` 使用 `try-finally` 删除渲染文件，防止磁盘泄漏。
6. **不限制 `applyPageLevelEntryFallback` 数量**：按用户要求保留，未加每页上限。
7. **`PaddleOcrProcessor.main` 中文路径保留**：按用户要求不修改。
8. **未执行 `npm run sync`**：本次未改动 CLI option，按 `CLAUDE.md` 提示无需 sync。
