# opendataloader-pdf 任务记忆 — 2026-08-07（流程图箭头 bbox 含填充箭头头）

## 目标（Goal）
- 修复流程图 `TYPE_ARROW` 的 bbox 不包含**填充箭头头尖**的问题：-84 页0 箭头1 的 bbox bottomY 应为 ≈244.87，而错误结果是 249.87（只含杆，不含三角尖）。
- 已实现并验证：opendataloader 内用现成 `GetDrawings`（PDFBox）提取 FILL 路径作为**回退候选**，恢复被合并容器吞掉的箭头1 头。

## 问题原因（Root Cause）
- veraPDF chunk 层在 `ignoreMCIDs` 模式下（`isIgnoreMCIDs = !isUseStructTree()`，`DocumentProcessor.java:760-762`）：
  `LineArtContainer.add` 会把同 MCID 组内的新 box **并入组内最后一个 box**。
- -84 页0 箭头1 的填充三角形头 bbox 因此被并入 MCID=118 大容器 `[133.58,148.57,462.98,284.97]`，
  **纯 artifacts 不可恢复**——`filledArtBoxes`（bbox-only `LineArtChunk`）里没有该箭头头，`findArrowBBox` 只剩杆 bbox `[298.5,249.87,299.5,267.97]`。
- 对照组：箭头2 的头部 bbox 幸运地以 bbox-only LineArtChunk 保留在 artifact 层 `[295.5,184.62,302.5,208.22]`，走 artifacts 路径正常，无需回退。
- 附加难点（本次会话定位）：PDFBox 与 veraPDF 坐标精度差异（0.00003 pt 级）。
  `extractPageFillBoxes` 提取的 fill `[296, 244.8699951171875, 302, 267.97003173828125]` 的 topY 比杆 topY 267.97 大 0.00003，
  使 `extendsAfter` 也判 true → `extendsBefore == extendsAfter` 判等被拒 → fill 被丢弃。

## 已实现方案（当前，已验证）：应用侧 PDFBox FILL 回退（workaround）
### 实现
- `DocumentProcessor.extractPageFillBoxes(String pdfName, int pageCount)`（:789）：
  - 用 `Loader.loadPDF(new File(pdfName))` **独立二次加载** PDF（见"管线限制"）。
  - 逐页 `GetDrawings.getDrawings(page, pageNo)`（`org.opendataloader.pdfbox` 包），只收 `FILL` / `FILL_STROKE` 且 `closePath` 非空且 `rect` 非 null。
  - 坐标换算（实证）：`GetDrawings` 输出为**左上原点、y 向下**；转 y-up 用 `bottom = pageHeight − rect.y1`、`top = pageHeight − rect.y0`；
    `pageHeight = page.getMediaBox().getHeight()`（-84 = 841.92）。
  - 按页存入 `Map<Integer, List<BoundingBox>>`；整文件加载失败 → WARNING 降级纯 artifacts。
- `ShapeRecognizer`：
  - 新增 `recognize(IDocument, Map<Integer,List<BoundingBox>>)`、`recognizePage(int, List<IChunk>, List<BoundingBox>)` 重载（旧签名委托新版，`ShapeRecognizerTest` 不破坏）。
  - `recognizeConnectorLines` 增 `fillBoxes` 参数；`findArrowBBox` **先 artifacts 后回退**：`pickArrowhead(shaft, filledArtBoxes)` 无果才试 `pickArrowhead(shaft, filterShapeCoincidentFills(fillBoxes, existingShapes))`。
  - `pickArrowhead(shaft, candidates)`：`overlaps` + **仅单端外伸 XOR** + `perpDim <= MAX_ARROWHEAD_WIDTH(15.0)` + `alongDim <= 3 × shaftAlong` + 多候选取**最小面积**。
  - `filterShapeCoincidentFills(fillBoxes, existingShapes)`：**只对已识别 `TYPE_RECTANGLE` / `TYPE_BAR_CHART` 过滤**（重叠 ≥ 50% 填充面积 且 形状面积 ≤ 10× 填充面积 才剔除）；
    **不检查 polyline**——箭头头合并后自己重建为 polyline，检查它会把回退修复反杀掉。
  - `MAX_ARROWHEAD_WIDTH` 改 `public static final`（供调用方预过滤）。
- 本次会话关键修复：新增 `ARROWHEAD_EXTENSION_EPSILON = 0.5`，单端外伸判断各带 ±0.5 pt 容差，消除坐标精度差导致的误拒。

### 优势
- 不动依赖、不动全局语义，只对"artifact 层找不到箭头头"的路径兜底 → **已有正常路径（-83、箭头2）零变化**（先 artifacts 后回退保证）。
- 直接复用现成 `GetDrawings`，无需重写内容流解析器。
- 双守卫（重叠+单端外伸+尺寸） + 形状重合过滤，实测不误认节点框/大容器。

### 不足 / 风险
- **二次加载整个 PDF**（PDFBox 独立 parse），大文件性能开销、且 `Loader.loadPDF` 资源靠 try-with-resources 关闭（务必保持）。
- 依赖 GetDrawings 的坐标语义（左上原点 y 向下），换算错误会静默污染回退结果。
- 回退守卫靠经验阈值（15pt / 3× / 0.5pt / 50% / 10×），对不同 PDF 绘制风格鲁棒性有限；多边形头/曲线头可能不满足"单端外伸 + 小面积"而漏回退。
- fill 噪声（阴影、渐变、装饰性填充）可能误选为头，靠 `filterShapeCoincidentFills` + 最小面积缓解，非绝对。

## 备选方案1（根因修复，**稍后实现观察**）：修复 veraPDF `LineArtContainer` 合并逻辑
- 位置：`D:\Code\JavaCode2\veraPDF-wcag-algs\src\main\java\org\verapdf\gf\model\factory\chunks\LineArtContainer.java`。
- 思路：`LineArtContainer.add` 在 ignoreMCIDs 时把同组新 box 并入组内最后一个 box。改为：**不合并闭合填充路径的 bbox**（或按 closePath/填充类型拆分/保留独立 bbox），使箭头头在 artifact 层直接保留 bbox-only LineArtChunk。
- 优势：
  - 从根因解决，所有被合并的箭头（及类似闭合填充图形）一次修复；
  - 应用侧**不再需要 PDFBox 二次加载**（省一次整文件加载，管线更干净）；
  - 不依赖 GetDrawings 坐标换算与回退守卫，逻辑更纯粹。
- 不足 / 风险：
  - 需修改并**重新构建/发布依赖**（veraPDF-wcag-algs 是外部库；opendataloader 依赖坐标需切换或 shading）；
  - 合并逻辑可能被其他 MCID 场景依赖，改动回归面大（需 veraPDF 侧全量回归）；
  - 工作量和风险高于应用侧 workaround，故先观察当前 workaround 效果。
- 稍后实现计划：本地对 `LineArtContainer.add` 做最小改动，用 -84 验证箭头1 头部 bbox 是否以独立 LineArtChunk 出现在 artifact 层，再决定是否正式发布；同时重跑 `ShapeRecognizerTest`/`ArrowE2ETest` 确认回退路径未被触发但仍正确。

## 备选方案2（实验性观察项，**稍后实现观察**）：启用 struct tree 模式（isIgnoreMCIDs=false）
- 思路：`StaticStorages.setIsIgnoreMCIDs(!isUseStructTree())`（`DocumentProcessor.java:762`）。若 `useStructTree=true` → `ignoreMCIDs=false` → MCID 容器不合并 → 箭头头 bbox 保留在 artifact 层。
- 优势：**零代码改动**（纯配置），理论上直接恢复所有被合并的箭头头。
- 不足 / 风险：
  - 整条管线语义改变：`ignoreMCIDs=false` 时 veraPDF 按 MCID 分组解析，影响文本/行内顺序、容器结构；
  - 与大量现有测试（依赖默认 `ignoreMCIDs=true` 行为）冲突，回归风险极高；
  - 引入对"文档是否带有效结构树"的依赖（无结构树时行为未知）。
  - **不建议作为生产默认**，仅实验性观察。
- 稍后实现计划：写临时测试在跑 -84 时置 `isUseStructTree=true`，观察箭头1 头部 bbox 是否出现在 artifact 层、以及其他 shape/文本输出是否漂移；若无回归可作为长期方向。

## 关键决策（Key Decisions）
- 先 artifacts 后回退，保证已有正常路径零变化。
- 回退候选只收 `FILL`/`FILL_STROKE` + `closePath`，减少噪声。
- 坐标换算：GetDrawings 左上原点 y 向下 → `y-up = pageHeight − y`。
- 守卫阈值：`MAX_ARROWHEAD_WIDTH=15.0`、`MAX_ARROWHEAD_LENGTH_FACTOR=3.0`、`ARROWHEAD_EXTENSION_EPSILON=0.5`、`filterShapeCoincidentFills` 的 `50%` / `10×`。
- `filterShapeCoincidentFills` 不检查 polyline（会反杀回退）。
- 管线限制：`preprocessing` 里的 `pdDocument` 是 **veraPDF** `PDDocument`，不可传给 PDFBox `GetDrawings`；须另行 `Loader.loadPDF(new File(pdfName))`（`org.apache.pdfbox.Loader` 已 import）。
- CLI JSON 不序列化 shapes → E2E 验证走临时测试，不走 CLI JSON。
