# 2026-11-02 生产日志降噪：`log.level` 与 `logging.level` 的生效顺序坑

## 0. 目标与现象

生产环境日志量偏大，希望把 `application-prod.yml` 的 `log.level` 从 `INFO` 改成 `WARN`。
改完只做「看一眼」，很容易误判为已生效——实际**对本服务自身的日志毫无影响**。

## 1. 两套配置入口

| 配置 | 谁读 | 作用 |
| --- | --- | --- |
| `log.level` | `logback-spring.xml` 第 5 行 `<springProperty name="log.level" source="log.level" defaultValue="DEBUG"/>`，用于 `<root level="${log.level}">` | 决定 **root** 级别 |
| `logging.level.<package>` | Spring Boot `LoggingApplicationListener` → `LoggingSystem` | 决定 **单个 package** 级别，**在 logback 配置加载之后应用**，因此优先级更高 |

坑就在第二条：`application.yml`（基础配置，**所有 profile 都会加载**）里原本写着

```yaml
logging:
  level:
    org.opendataloader.pdf.server: DEBUG
```

于是 prod 上 `org.opendataloader.pdf.server.*` 恒为 DEBUG，`log.level: WARN` 完全压不住它。

## 2. 实测（临时 Spring 探针，跑完即删）

探针方式：`SpringApplicationBuilder(...).run("--spring.profiles.active=prod")`，
读 `ch.qos.logback.classic.Logger#getEffectiveLevel()`（必须用命令行参数设置 profile，
`application.yml` 里的 `spring.profiles.active: dev` 会盖掉 builder 的 `properties`）。

| 版本 | profile | root | `org.opendataloader.pdf.server.*` |
| --- | --- | --- | --- |
| 仅改 `log.level: WARN`（改前） | prod | WARN | **DEBUG**（`isInfoEnabled=true`） |
| 方案 A（当前） | prod | WARN | **WARN**（`isInfoEnabled=false`） |
| 方案 A（当前） | dev | DEBUG | DEBUG（开发环境不变） |

## 3. 修改

1. `application.yml`：删除 `logging.level.org.opendataloader.pdf.server: DEBUG`，留注释说明不要在此处 pin（否则任何 profile 的 `log.level` 都会被它盖掉）。
2. `application-prod.yml`：追加 `logging.level.org.opendataloader.pdf.server: WARN`，与 `log.level: WARN` 保持一致。

## 4. 影响面（生产）

- **消失**：每条消息的成功链路 INFO——`processing pdf for pulsar` / `download pdf success` /
  `process pdf success, businessId=..., jsonUrl=...` / `send result message payload` /
  `complete_display=true ... skip`；以及 `TempWorkspaceSweeper` 的启动 INFO、每轮无事可做的 DEBUG。
- **保留**：所有 ERROR/WARN——`handleReceiveMessage failed`、`message processing TIMEOUT ... Stuck worker stack`、
  `handed N temp directories of the abandoned worker`、`swept stale temp directory`、
  `temp directory ... could not be deleted on release`、`PdfBoxNoiseFilter` 之外的 PDFBox 真错误。
- **不受影响**：core 侧 `java.util.logging`（`LOGGER.log(Level.INFO, ...)`）走 JUL 默认 ConsoleHandler，
  不经过 logback，容器 stdout 里照旧（若要一起压，需要 `SLF4JBridgeHandler.install()` 或改 core 的 logger）。
- 其它 profile（dev/prepub/test）未改动，仍是 DEBUG。

## 5. 踩坑

- 只有把 `--spring.profiles.active=prod` 作为**命令行参数**传入，`application-prod.yml` 才会覆盖
  `application.yml` 里的 `spring.profiles.active: dev`；用 builder `.properties()` 会得到假结果。
- `logback-spring.xml` 首行仍是 `<configuration debug="true" scan="true">`，启动时打印 logback 自身状态，
  与降噪目标相反，建议后续改 `debug="false"`（本次未改，避免动无关行为）。
