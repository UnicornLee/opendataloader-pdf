## 结论速览（TL;DR）

三个现象由**同一套边界/判据规则**造成，方向相反：

1. **第 7 页中部图未识别**：图形被正确聚成 22 个 polyline 的大组，但 cluster 内收集到 veraPDF 线条预处理把"方框 + 连线"切出的表格边框
   （最大 `cells=9`、面积比 0.235），命中 `FlowchartProcessor.isRegularTable()` 的**硬门限 `maxCells>=6 → 立即判为常规表格`（不看面积）**
   → 整张图被否决 → 不截图；线被表格吃掉 → 输出成 6 个 `lattice_table`。
2. **第 7 页下部图吞标题**：标题是 `SemanticHeading`（高 **23.32pt**），只比 `BODY_TEXT_MAX_HEIGHT=24pt` 低 0.68pt 未被"正文保护"拦下；
   它与图顶端间隙仅 **1.77pt < COLLECTION_MARGIN(2.0)** → 被收集，cluster 顶上移到标题顶边 → 标题进截图并从正文消失。
3. **第 8 页线上标签漏截**：两处 `15.8% (consolidated interest)`（`CustomSemanticParagraph`，高 6.71pt）与图顶端间隙
   分别为 **3.4574pt / 2.97pt**，**均 > COLLECTION_MARGIN(2.0)** → 未被收集 → 既不进截图也不从正文移除。

即：**同一套「2.0pt 邻接容差 + 无上界的生长 + 纯高度的正文门限」**，在第 7 页造成"吞正文"，在第 8 页造成"漏标签"。

修复后：中部图与下部图各自独立截图、标题保留在正文且不在截图内、`lattice_table` 8→0、第 8 页两张截图分别上扩 10.21pt/10.24pt 把线上标签纳入并从正文移除。

## 观测手法（可复用）

1. **临时插桩**：给 `FlowchartProcessor` 加 `-DdbgFlow=1` 开关的日志（group 列表、每次 collect 的 ADD/NO、merged 统计、判定各条件与拒绝原因、
   `isRegularTable` 的 `maxCells/面积比`）。用完 `git checkout` 还原。
2. **渲染对照**：本地 pdfbox 3.0.4 单文件跑 `tmp_output/RenderPages.java` 把原 PDF 第 7/8 页渲染成 PNG，
   与解析出的 `imageFile*.png` 目视对照（确认"标题被吞""标签漏截"）。
3. **单页加速 A/B**：`DebugCorpusTmp` 支持把 `Config.setPages("2,34,35,52")` 传进去 —— 大文档单次实验从 ~150s 降到 ~20s。
   本轮靠它确认 **A1、B2、ShapeRecognizer 都不是大文档 p2 出现整页截图的原因**，避免在错误方向改判据。
4. **全量语料跑分**：临时类 `DebugCorpusTmp`（每份 PDF 独立 JVM，`ProcessingDeadline.start(8min)` 兜底）产出
   `corpus_*/<name>.digest`（每页每项的 `类型/bbox/文本前缀`），4 分片并行，改动前后用 python 逐行 diff。
   PowerShell 侧用 `Start-Process -WindowStyle Hidden` 起 4 个分片；`Out-File` 必须带 `-Width 100000`（默认 80 列会截断长日志行）。

## 定位过程（从现象到根因）

### 现象 1：中部图被当成"若干不规则表格"

1. 日志显示中部图的 shape 全部识别成功（22 个 polyline、120 个组件），且被 `groupShapes` + 吸收逻辑正确合成**一个大组**。
2. 判定链上只有一条 REJECT：`isRegularTable`。cluster 内收集到 **92 个 TableBorder 条目**（去重后 6 个不同 bbox），
   最大 `cells=9`、`areaRatio=0.2352`。
3. 这些表格来自上游 veraPDF `LinesPreprocessingConsumer.findTableBorders()`：它按"水平线×垂直线交叉"把线归入同一个 `TableBorderBuilder`，
   而流程图的方框边 + 节点间连线正好互相交叉 → 被切成 2x2 / 3x3 的"网格"。
4. 原判据 `cells>=6 → true` 不看这些"表格"是否真的占据了 cluster → 一张 22 个形状的图被一个 3x3 碎片否决。
5. 因为没被截图，这些线的 `TableBorder` 留在页面上 → 输出成 `lattice_table`（用户看到的"不规则表格"），图内标签也全部留在正文。

### 现象 2：下部图吞掉上方标题

1. 下部图（`group[12]`）的 cluster 在第一次收集时就吸到了标题：标题 bottom `158.943` 与 shape 组顶 `157.171` 只差 **1.7714pt < 2.0**。
2. 该标题是 `SemanticHeading`，高 **23.3215pt**（两行，宽 445.1pt），比 `BODY_TEXT_MAX_HEIGHT=24pt` 低 0.68pt → `containsBodyText` 未拦截。
3. 于是 `mergedBox` 顶被抬到标题顶边 `182.2616`，截图范围变成 `[62.190, 183.261]`，标题被裁进截图并从文本层移除。

### 现象 3：第 8 页线上标签漏截

1. 标签 `15.8% (consolidated interest)` 是 `CustomSemanticParagraph`（高 6.71pt），与图顶端间隙 2.97pt（上部图）/3.4574pt（下部图）。
2. `collectOverlappingContents` 用 `contentBox.overlaps(searchBox, COLLECTION_MARGIN=2.0)` → 两处都判不重叠 → 未收集。
3. 标签高度远小于任何"正文门限" → 只要被收集就会被吞；因此唯一卡点就是这 2pt 容差。

## 修复设计（含被否掉的方案）

- **表格判据（A1）**：`isRegularTable` 去掉 `cells>=6 → true`，统一为"**最大表格面积 / cluster 面积 > 0.4 才判常规表格**"。
  理由：真表格页面上 cluster 与表格基本重合（比值 ≈ 1），而流程图里的表格只是碎片（本例 0.235）。
- **正文块识别（B1）**：新增 `findProseBlocks(pageContents)` —— 文本块按 topY 降序排列后，只要与**同栏（水平重叠）**的另一文本块
  垂直间隙 ≤ `1.5 × min(两者高度)`，两者都判为"正文段落"。这些块在**收集阶段就被跳过**（不收集 → cluster 不会被正文撑大，
  也就不会吸收无关 group），并在 `dropBodyTextBlocks` 中剔除。
- **标签容差（B2）**：`isDiagramLabel` = 文本类且高 ≤ `12pt`；标签用 `LABEL_COLLECTION_MARGIN` 容差，其它用 `COLLECTION_MARGIN(2.0)`。
  **删除"宽度 ≤ 0.5×shape 组宽"的相对判据**（图内标签可以比节点框更宽；双栏正文行与标签在几何上不可分，靠"是否成段"区分）。
  容差取值的实测依据：第 8 页的 `15.8% (consolidated interest)` 与图形顶端间隙 3.0/3.46pt，**第 7 页中部图上方的同一个标签间隙 6.02pt**
  （用户第二轮反馈"第 7 页这个也没截进去"）→ 容差由 **4.0 放宽到 8.0**。只对短标签生效；成段正文已被 `findProseBlocks` 事先排除。
- **图形内部（B3，第二轮按用户追加口径补充）**：`absorbInteriorText` —— 收集与剔除正文之后，把**完全落在图形 region 内**
  （`region.contains(box, 1pt)`）的文本块补回 cluster，使其随截图一起从正文移除。
  理由：`findProseBlocks` 会排除"成段的相邻短行"（通常是正文），但图形**内部**的成段短行恰恰是图表标签
  （第 7 页中部图的 `100%`/`50%`/`NTU`/`NCPM`/`HPMCL`/`NTGPM` 列）。region 由图形构成、不会因正文扩张，
  所以"落在 region 内"是安全的强信号；且吸收不改变 region（块本就在内部），不会反向放大截图。
- **页面级防护**：`isPageFrameGroup`（单形状面积 > 页面 40% → 页面边框/背景，跳过）、
  `coversWholePage`（cluster 面积 > 页面 70% → 不截图）。需要真实页面尺寸 → 新增
  `processFlowchartGroups(..., pageNumber, pageWidth, pageHeight)` 重载，`DocumentProcessor` 传 `pageWidths/pageHeights`；
  旧 4 参版委托并传 `0,0`（页面判据关闭，既有单测不受影响）。
- **截图插入顺序**：新增 `addInOrder` 按 topY 降序插入（原来 append 到列表末尾）——
  否则同页两张截图在列表里相邻，`ConsecutiveImageProcessor`（gap ≤ 0.5×较小高度）会把它们粘成一张，把中间标题卷进截图。
- **箭头识别（第 6 项）**：`recognizePolylines` 跳过"共线直链"；`recognizeConnectorLines` 接受
  `chain.size()!=1 && isStraightChain(chain)` 的链（原来只认单段链）→ 被 PDF 内容流/标记内容拆成多段的连线终于能算箭头。

被否掉的方案：
- 只用"宽度比例"筛标签 → 双栏排版页的正文行（宽 225 / shape 组宽 504）与标签无法区分，实测吞 64 行正文。
- 用"页面内容并集"当页面尺寸代理 → 内容少的页面 cluster/page ≈ 1，被当成整页全部拒绝（4 个单测红）。
- 改 veraPDF 上游 `findTableBorders` 让"方框+连线"不构成表格 → 真表格正是"闭合方框+交叉线"，风险高收益低
  （core 侧识别为流程图后会 `removeAll` 掉 cluster 内的 TableBorder，`lattice_table` 已消失），本轮不动。

## 实现中踩的 4 个坑（重要）

1. `findProseBlocks` 的间隙符号写反（应为 `box.bottom - other.top`）→ 几乎每个"下方有文本"的块都被判成正文 →
   标签全被排除 → 第 7 页下部图与第 8 页标签**集体消失**。**症状与"判据过严"完全相同，极易误判为策略问题。**
2. 相邻阈值用 `max(两者高度)` → 尺度被放大（标题 23pt → 阈值 35pt，31pt 的间隙被当成"相邻行"）→ 改用 `min`。
3. 用"页面内容并集"当页面尺寸代理 → 单测里 cluster/page ≈ 1 → 全部被当成整页拒绝（4 个单测红）。必须用真实 mediabox。
4. 截图 append 到列表末尾 → `ConsecutiveImageProcessor` 把跨页两图粘成一张（标题被卷进截图）。改为按 topY 有序插入。

回归过程中的两个坑（供后续复用）：
- 首次全量跑有 7 份文档**没有产物**：`DebugCorpusTmp` 在 `PrintWriter` 打开文件后被 OOM/崩溃打断 → 留下 **0 字节 digest**，
  在 diff 里表现成"整份文档的文本全部消失"（大文档一度显示消失 3504 行），极易误判为严重回归。
  **判定手法**：先比对双方 digest 的**行数**与**文件体积**（`tmp_output/lines_count.py`、`check_sizes.py`），再谈内容差异。
- `Config.setPages(...)` 的"单页跑"与"全页跑"结果一致（已用大文档 p2 交叉验证），可用于快速 A/B；但**全量跑必须给足堆内存并检查产物完整性**。
- 之后又碰到第二种不完整产物：`ProcessingDeadline` 超时 → digest 只剩 `=== <name> FAILED ms=...` 一行。
  两个 1000+ 秒的文档（35MB 扫描件、100+ 页表册）在 10 分钟预算下 FAILED，而**同样的预算上一轮曾经成功**（差别只是当时机器负载更低）。
  这类 FAILED 在 diff 里同样表现成"整份文档的文本全部消失"（大文档一度显示消失 9955 行）。
  **结论：预算要按文档体积/页数分配（大文档 ≥ 30 分钟），补跑时不要与其它分片并行；比对前一律先跑 `check_sizes.py` + `lines_count.py`。**
