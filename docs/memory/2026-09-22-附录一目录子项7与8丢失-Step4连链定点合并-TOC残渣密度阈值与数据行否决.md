## 二、根因定位（证据链）

### 阶段 0：确定走哪条路径

`extractCatalogBookmarksFromJson` 得到 19 条目录（6 个一级），附錄一/附錄二在 TOC 里没有子项 →
子树由 `fillCatalogChildrenFromPageData` 的 L2 pass 补全，切片 `(24,1)-(28,1)`。

### 阶段 1：切片里有什么（反射探针 `TmpSliceProbe`，调用真实私有方法）

9 个候选**全部是 `#`/ARABIC 模板**：

| # | 位置 | 字号 | 行数 | fullText 长度 | 文本 |
|---|---|---|---|---|---|
| 1–6 | p24 id3/5/7、p25 id2/4/8 | 12.5 | 1 | 6–13 | `1.  股本` … `6.  收購守則` |
| **7** | **p26 id14** | **9.0** | **3** | **127** | **`1 . United Century及King Partner均為…`（以「。」结尾）** |
| 8 | p26 id17 | 12.5 | 1 | 18 | `7.  本公司於過去六個月購回之股份` |
| 9 | p27 id2 | 12.5 | 1 | 6 | `8.  股價` |

第 7 项是 p26「主要股東持股」表下的**附註 1**（上一行是 `附註：`）。
`matchPrefix` 只要求"数字 + 空白/点号"后缀（`hasValidBookmarkSuffix` 允许空白），所以 `1 . ` 命中
常量 "1" → 被当成 value=1 的合法候选。

### 阶段 2：周期过滤本该删掉它，却被保守豁免救下

`applyPeriodEndFilter`：8/9 = 88.9% 不以「。」结尾（> `PERIOD_FILTER_RATIO` 80%），本该删掉
"以「。」结尾的少数派"（正是这条脚注）。但：

```java
// PageBookmarkProcessor.applyPeriodEndFilter（改动前）
if ((total - endsWithPeriod) > total * PERIOD_FILTER_RATIO
        && minorityContainsValueOne(candidates, false)) {
    return candidates;   // ← 少数派里有一个 value=1 → 整条豁免
}
```

探针实测 `applyPeriodEndFilter` **in=9 → out=9**（未过滤）。该豁免由 commit
`b19b126`（2026-09-10，"preserving value=1 anchors during period-end filtering"）引入。

### 阶段 3：单趟连链被杂项"偷走游标"

`cleanCandidatesLocal` Step 2 把 1..8 切成三个 +1 极大段；Step 3 按"起始值"排序得到
`g1[1..6](start=1,p24)`、`g2[1](start=1,p26)`、`g3[7..8](start=7,p26)`；改动前的 Step 4 是
**单趟线性扫描**（游标 `currentChainMax`，只判 `currentChainMax+1 == groupMin`）：

```
chain1=[g1] max=6 → g2: 6+1=7 ≠ 1 → 新链 chain2=[g2] max=1（游标被重置）
                  → g3: 1+1=2 ≠ 7 → 新链 chain3=[g3]
```

`[7,8]` 自成一链，被 Step 4.8（`chains.removeIf(chain -> ... chain.get(0).get(0).value != 1)`，
2026-09-11 commit `9026bfd` 引入）整条丢弃；Step 5 只剩 `[1..6]` → **7/8 消失**。

注意 Step 4 的注释原文写的就是"the contiguous runs still merge into one chain while the stray
forms its own chain"——**设计意图是对的，实现（单趟扫描）没有兑现**。

显形的第二个条件。另确认：`6. 收購守則` 下的伪脚注子项**旧版同样存在**，属老问题非本次回归。

### 阶段 5：page_bookmarks 同病但机制不同

## 三、已实现方案（三处改动，均在 `PageBookmarkProcessor.java`）

### 3.1 Step 4 连链改为定点迭代合并（方案 C，用户口径）

单趟扫描改为：**每轮从 pending 里找 `min == chainMax+1` 的分组并入，直到无可并**。
效果：`g1[1..6]` 与 `g3[7..8]` 合并成 `[1..8]`（g2 脚注单独成链、宽度 1 落选）→
探针实测 `cleaned -> 8`、extractLevel 输出 **1..8**，且**不依赖周期过滤**（脚注仍在候选里）。
javadoc 同步改为"runs are merged until no chain can absorb any remaining run"。

### 3.2 C3：TOC 残渣阈值随链长缩放

定点合并让 `202304271682510470028924` 的 `#、` 链变长（5 → 39）后，反而触发
`isTocLikeGroup`（Step 4.5）的**绝对阈值**（size>5 时 `pairCount>=2 || maxRun>=3` 即整链一票否决）
→ 整条模板在该父切片被丢弃 → 层级选择退回 `（#）`，`1、遵循企业会计准则的声明…5、同一控制下…`
**全文档 0 残留**。机制用"关闭 Step 4.5"变体确认（该条目 0→2 恢复）。

修复：`tocResidueThreshold(size) = max(2, ceil(size × TOC_RESIDUE_DENSITY))`，`TOC_RESIDUE_DENSITY = 0.5`。

### 3.3 数据行否决（候选级）

C3 让更多链活下来，也放进了**编号表格行**。给两条候选收集路径
（`collectJsonCandidates` 与 IObject 版 `collectCandidates`）加否决：

```java
private static final java.util.regex.Pattern DATA_ROW_PATTERN =
    java.util.regex.Pattern.compile("\\d[\\d,.]*\\s+[\\d,.]*\\d");
```

"数值 + 空白 + 数值"（`13,525,400 3.8644`、`14 11 135 352`）→ 非候选。
误杀防护实测：`43、 1 年内到期的非流动负债`（空格后非数字）✅ 存活、`2.00港元`（无空格）✅、
`2019 年股票期权…` ✅。

## 五、附带发现与遗留

1. **密度信号被证伪**：给 `isTocLikeGroup` 加统计日志跑全语料（33182 次调用）——
   好链 pairDensity 0.20~0.29（45 链 pair=13/run=5），坏链 0.035~0.27（38 链 0.053、36 链 0.194、
   85 链 0.035、11 链 0.273）；字号也分不开（`02665` 真标题 10.0pt，表格行反而 11.0pt）。
   ⇒ **C3 的阈值在数学上无法既保住好链又滤掉表格行**，噪声是"定点合并让更多链活下来"的本质代价。
2. **已接受的残留**（用户选 A）：`02665_圖達通` 软件著作权 38+34 行、`202410231785072233292001596`
   估值说明句子 + 26 行股东名单、`202304281682603453761936` 租赁条款句子、
   `6. 收購守則` 下的 9pt 脚注子项（C/老问题）。
3. **数据行否决的级联副作用**：`202409271785065118796017983`（−2 条真标题、+7 条）、
   `202504281785145532722080227`（−4 条审计报告标题、+7 条表段标签）——"删候选 → 链选择全局重排"
   所致；替代方案（候选保留但仅在发射时跳过）会让表格行链继续参与层级投票，有另一种失败模式，未采用。
4. `page_bookmarks` 侧"缺 7/8"是老问题（旧版同样缺），非 `b19b126` 回归。
5. `matchPrefix`/`hasValidBookmarkSuffix` 对"数字 + 空白"的宽松匹配是表格行/脚注入池的根源，
   若未来要收紧需先过全语料。
6. core 全量单测本轮未重跑（最近一次 37F/20E，均为已知环境性失败）。
