### Step 5：定位代码根因

`DocumentProcessor.processDocument` Loop 2（L477）调用 `TableBorderProcessor.processTableBorders`。其核心逻辑（L81-100）：

```java
for (IObject content : contents) {
    TableBorder tableBorder = addContentToTableBorder(content);  // ← 命中表格则整个 TextChunk 加入 cell
    if (tableBorder != null) {
        ...
        if (content instanceof TextChunk) {
            TextChunk textChunk = (TextChunk) content;
            TextChunk textChunkPart = getTextChunkPartBeforeTable(textChunk, tableBorder);  // ← 又切「边框前文本」
            if (part 非空) newContents.add(textChunkPart);
            textChunkPart = getTextChunkPartAfterTable(textChunk, tableBorder);
            ...
```

- `addContentToTableBorder`（L148-166）：TextChunk 与 cell 相交 → `tableBorderCell.addContentObject(content)`，**整个**文本进 cell。
- `getTextChunkPartBeforeTable` → veraPDF `TextChunkUtils.getTextChunkPartBeforeBoundingBox` → `getSymbolEndIndexByCoordinate(bbox.leftX)`，实现为：

```java
public Integer getSymbolEndIndexByCoordinate(double coordinate) {
    for (int index = this.symbolEnds.size() - 1; index >= 0; index--) {
        if (symbolEnds.get(index) < coordinate) {  // 严格小于
            return index;
        }
    }
    return null;
}
```

首符号起点 60.24 < 边框 60.25 → 判定存在「表格前文本」→ 切出**第一个字符**「货」加到页面 newContents。

**根因链条**：同一 TextChunk 既因与 cell 相交被整体加入表格 cell，又因首字符凸出边框 0.01 被「表格前文本」切分逻辑切出残留 —— 同一文本被复制两份。只影响「文本起点恰好凸出表格左边框」的表格，故只有表格2、只丢每行首列首字符。

## 修复改动（方案 A，用户确认后实施）

只改 `java/opendataloader-pdf-core/src/main/java/org/opendataloader/pdf/processors/TableBorderProcessor.java`：

1. 新增常量（L42-52）：
```java
private static final double SPLIT_PART_TABLE_OVERLAP_RATIO = 0.5;
```

2. 新增方法：
```java
private static boolean isSplitPartInsideTable(TextChunk part, TableBorder table) {
    return part.getBoundingBox().getIntersectionPercent(table.getBoundingBox())
            > SPLIT_PART_TABLE_OVERLAP_RATIO;
}
```
`BoundingBox.getIntersectionPercent`（veraPDF，L481）：返回本 bbox 与参数 bbox 的交集面积占**本 bbox** 面积比例，异页直接 0.0。

3. before/after 两处切分点接入判断，part 与表格重叠 > 50% 即视为误切丢弃：
```java
if (textChunkPart != null && !textChunkPart.isEmpty()
        && !textChunkPart.isWhiteSpaceChunk()
        && !isSplitPartInsideTable(textChunkPart, tableBorder)) {
    newContents.add(textChunkPart);
}
```

真正的表格前/后文本与表格 bbox 交集≈0，不受影响。

## 相关知识沉淀

- 本项目 PDFBox 为 3.0.4：文本位置调试用 `PDFTextStripper.writeString(String, List<TextPosition>)`，以 `getText(doc)` 驱动，不要用已移除的 `PDFTextStreamEngine`。
- veraPDF `getSymbolEndIndexByCoordinate` 用严格 `<` 比较，坐标有浮点误差的文本会被切成「边框外部分」；遇到「表格后多出一排单字符」这类现象，先比对游离字符坐标与表格边框坐标，再查 before/after 切分路径。
- 定位手法：先比 JSON 结构确认「多出来的是什么」，再用底层工具验证 PDF 原文只绘制一次（排除 PDF 问题），最后用坐标差锁定触发条件并查切分代码。
