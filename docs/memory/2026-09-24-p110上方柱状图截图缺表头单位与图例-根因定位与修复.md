# 2026-09-24 第110页“上面的柱状图没有截全”——根因定位与修复

样本：`docs/pdf/20260507AN202606291826520711.pdf` 第 110 页（本文中的页号 = JSON 的 `page_index`）。
该页有 2 个柱状图（上下各一个，每个柱状图含“全球”“中國”两块绘图区 + 一张复合年增长率小表 + 图例 + 单位）。

## 1. 现象

| 位置 | 截图 bbox | 内容 |
|---|---|---|
| 下方柱状图 | `x[70.87,524.41] y[495.89,662.56]` | 表头块（增长率表 + 深蓝表头 + 图例“全球/中國”）、单位“千台”、坐标轴、两块绘图区、年份与（估計）标签 |
| 上方柱状图 | `x[87.43,525.13] y[141.24,262.09]` | **只有坐标轴 + 两块绘图区**；表头块、图例、单位“人民幣十億元”留在文本层 |

上方图的表头块在 JSON 里表现为 `lattice_table x[348.2,520.3] y[94.6,126.9]` 与 4 行 text（`y 96.8-136.7`），即用户看到的“上面的柱状图没有截全”。
两张同类图表，一张连表头都截进去了、另一张只截了绘图区，属不一致。

## 2. 定位过程

### 2.1 确认截图内容与 bbox 完全一致
按 JSON bbox 从整页渲染（pypdfium2, scale=2）裁剪后与 `imageFilexxxx.png` 逐像素比对：一致。
→ 问题不是“渲染裁错”，而是 **bbox 本身太小**。

### 2.2 找出 bbox 顶边的来源
用 pdfplumber 取第 110 页 60–285pt 的 rects/curves/lines/words：
- 绘图区最高元素：最高柱顶 `y=152.88`；刻度“7,000” `y=143.64-150.23`；
- 单位“人民幣十億元” `y=129.80-136.67`；
- 上方图 bbox 顶 `141.24` 处**没有任何 PDF 对象** → 该值来自 veraPDF 文本 bbox（比字形框高约 2.4pt 的行高外扩）。

### 2.3 临时日志（`BarChartProcessor`，`pageNumber == 109` 时打印）
在 `processChartGroups` 的增长循环里打印每轮吸收的对象：

下方图（尾部日志）：柱子 → 数值/刻度段落 → 单位“千台”段落（与其重叠 0.3pt）→
`TableBorder x[114.41,286.98] y[264.64,297.81]`（重叠 0.35pt）→ 深蓝表头块 + 图例色块 + 表头文字 → 定格 `y[131.14,297.81]`（= top-down 495.89–662.56）。

上方图（首段日志）：初始组 = 右侧面板（`polyline` 轴线 + `bar_chart` + 4 根小柱），
第 1 轮吸收到刻度/数值段落 `y[642.10,652.46]`（top-down 141.24–151.60）后**再无任何吸收**，
定格 `y[531.61,652.46]`（= top-down 141.24–262.09）。

## 3. 根因

1. 图表区域是从柱子出发、**每轮只吸收与当前框相距 ≤ `COLLECTION_MARGIN`(1pt) 的对象**长大的；
2. 上方图在“刻度/数值段落 bbox 顶 141.24”与“单位文字 bbox 底 136.67”之间有 **4.54pt 空隙 > 1pt** → 链条断掉，单位、图例、表头块全部留在框外；
3. 下方图只是恰好：刻度段落与“千台”重叠 0.3pt、再往上与表框重叠 0.35pt → 整块表头被连带吸收。
   **两张图的差异是像素级巧合，不是设计差异**；
4. `expandToChartRegion` 的补全只覆盖左/下（y 轴、x 轴、刻度标签、类别标签）与**下方/右侧**图例，
   没有“绘图区上方表头块”的处理 → 断链后没有任何机制能把单位/图例/表头补回来。

## 4. 修复

`BarChartProcessor`（仅此一个文件）：

- 新增常量 `VERTICAL_LABEL_MARGIN = 8.0`（垂直方向给短标签的额外余量）、
  `VERTICAL_LABEL_OVERLAP_RATIO = 0.5`（标签与区域的最小水平重叠比例）；
- 新增 `isVerticallyAdjacentLabel(label, box)`：标签与框水平重叠 ≥ 50%，且位于框的**正上/正下方 ≤ 8pt**；
- 增长循环的判据改为：
  `contentBox.overlaps(screenshotBox, COLLECTION_MARGIN) || (isShortSingleLineText(content) && isVerticallyAdjacentLabel(...))`。

**只放开垂直方向**：左右方向仍用 1pt，因此像 p113 那种挂在绘图区右侧的“複合年增長率（2021年至2025年）”列表头不会被拉进截图（这是 2026-09-24 回退掉的那版补丁 `tmp_debug/bar_chart_p110_p113.patch`（`LABEL_COLLECTION_MARGIN=8` 全方向 + `absorbCoveredLabels` + `fitScreenshotToContents`）与本次的差别所在）。
