## 完整定位过程

### Step 1. 用户直觉先行
- 用户原话：「"(1) / (2) / ....../ (7)" 都是挨着的，一级目录没做相邻的校验吗？我记得对相邻的目录是有校验的，难道只针对二级和三级目录？」
- 这给了一个非常精确的方向：L1 路径**漏掉了目录残留 (TOC residue) 校验**。

### Step 2. 摸代码定位结构
- `PageBookmarkProcessor.selectTemplateForLevel` 排序键（path 内顺序）：
  ```java
  int fontCmp = Double.compare(b.averageFontSize, a.averageFontSize);
  if (fontCmp != 0) return fontCmp;        // ① 字体大者优先
  if (level == 2) { /* 密度比较 (density = size/pageSpan) */ }
  int countCmp = Integer.compare(b.candidates.size(), a.candidates.size());
  if (countCmp != 0) return countCmp;      // ② 多者优先
  int indentCmp = Double.compare(a.averageLeftX, b.averageLeftX);
  if (indentCmp != 0) return indentCmp;    // ③ 左偏者优先
  int pageCmp = Integer.compare(a.firstPageIndex, b.firstPageIndex);
  if (pageCmp != 0) return pageCmp;        // ④ 首页靠前者优先
  return Double.compare(b.firstTopY, a.firstTopY); // ⑤ 首条顶部位置高者
  ```
- `cleanCandidates` (L1)：只调 `hasOverlongEntry`（单条 > 200 才丢整段）。
- `cleanCandidatesLocal` (L2/L3)：在最后一步多了 `chains.removeIf(chain -> isTocLikeGroup(flattenChain(chain)));` 镜像。
- `isTocLikeGroup` 规则（`function -> 决策`形式）：
  | 规则 | 触发条件 |
  | --- | --- |
  | Rule 1 | section 内任一条 `fullText.length() > MAX_ENTRY_TEXT_LENGTH` (= 200) |
  | Rule 2a (size≤5) | 同页相邻 `relatedId` 出现 ≥ 1 对 |
  | Rule 2b (size>5) | 同页/跨页相邻 `relatedId` 出现 ≥ 2 对；或同页 `relatedId` 连续 run ≥ 3 |

**已确认**：L1 路径**完全没有 TOC 残留判定** → 这就是用户直觉锁定的根因。

也就是说 Plan ① 把"body 段当 L1"挡住了，但 `#/ARABIC`（`1. xxx` 风格、35 entries、font 10.45）以 **count** 优势赢得了 `X、/CHINESE`（`一、` 风格、15 entries、font 10.45）—— 排序键 font 平手后只看 count，于是选 35 不选 15。

### 二级根因（一句话）
排序键 `count` 比 font 退一步生效。当章节标题数（15）< 子目录条目数（35），`1.` 模板自动胜出；这只看数量不看"是否跨整个文档"，于是局部密集的子目录也能赢全局稀疏的章节主干。

### 二级修复候选（**尚未动手**，等用户拍板）
1. **下放 L2 的密度键到 L1**：现有 L2 用 `density = size / pageSpan`，低密度者胜。`#、` 家族跨 pageSpan=15、size=15（密度 1.0），`#` 家族集中在 pageSpan=30、size=35（密度 1.17）—— 期望 1.0 < 1.17 让 `一、` family 胜出。**改动最小、跨语种友好**（推荐）。
2. **L1 spread 启发**：同一模板候选若在文档里多次 value=1 复位 / 跨多个不相邻的章节，越像真 L1 越优先。可行但实现复杂。
3. **中文数字模板 L1 加权**：直接给 `X、` template 在 L1 加权，简单但解释性弱。

## 经验教训 (Memory)
- `cleanCandidates` 与 `cleanCandidatesLocal` 历史是不对称的（L1 无 TOC 残留过滤）。改 L1 路径时务必镜像 L2/L3 的策略，否则易出"body 段上位"的诡异结果 —— 也是用户当初提示的"应该有相邻校验"。
- L1 排序键"大字体优先"是个朴素启发，在 PDF 内部有多种 section、字号混排（同一份 PDF 同时有审计报告大字号 12 pt + 财务报告附注小字号 10.45 pt）时极易翻车。本任务反映这一点。
- 跑真实数据时除了看 `expected count` 还应看"是不是想要的层级风格"。本任务的二级问题就是只看 `n=7` 就放行，结果下一层 count=`35` 接着出锅。
- `isTocLikeGroup` Rule 2 的 size-threshold（≤5 / >5）和"同页相邻" / "跨页相邻"双轨判定，对 L1 也是直接可用的，**没有写新规则**的需要。
- 关键 debug 切入口：临时插 `System.err.println` 看 `cleaned n + avgFont` —— 比读代码推断更可靠。
